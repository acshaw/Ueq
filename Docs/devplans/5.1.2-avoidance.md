# 5.1.2 — Combat Pipeline: Avoidance Roll

**Status:** ✅ Done — verified in-editor 2026-07-15. AV1's data gap resolved: shipped as the
piecewise-linear approximation (isolated in `AvoidanceCurve.cs` so the real full table can drop in later
with zero resolver changes).

**Second-to-build of four sibling devplans** (see `5.1.1-hit-roll.md` for full numbering/build-order/scope
notes: this project builds 5.1.1 → 5.1.3 → **5.1.2 (this one)** → 5.1.4). Depends on 5.1.1 (the hit tier this
step may downgrade to Miss) and 5.1.3 (Riposte's counter-attack reuses Step 3's damage code). Grounded in
`docs/eventide_combat_pipeline.md` §3 ("Step 2 — Avoidance Roll, DEFINED — IMPLEMENTATION PENDING").

## Grounding
Design doc §3.1's waterfall model (Riposte → Parry → Dodge, each binary, each firing only if the previous
failed) is architecturally locked. §3.3's Dodge curve (Agility-driven) is given as 6 summary breakpoints, with
an explicit note that the FULL per-point Agility 1–250 table exists "in conversation history" but isn't in
this document. §3.4 says Parry/Riposte reuse Dodge's curve *shape* with Dexterity as input, but their own
curve *values* are named tuning parameters, not yet differentiated from Dodge. §3.5 defines Riposte's counter
-attack behavior (bypasses Step 2 and Step 4, uses Step 3 only, reduced damage — percentage TBD).

## Decisions

### AV1 — Avoidance curve — **RECOMMEND, one flagged data gap**
Build a piecewise-linear curve from the design doc's 6 given Dodge breakpoints (Agility 1–50→0.1%,
51–75→0.136–1.0%, 76–100→1.16–5.0%, 101–135→5.14–10.0%, 136–209→10.07–14.93%, 210+→~15% asymptote) as the
initial implementation — the ranges effectively ARE usable control points for interpolation, clearly
commented as an approximation pending the fuller table.

**If you have or can pull the full per-point table from the design conversation this doc references, that
directly replaces this approximation — flag it and I'll use the real curve instead of the piecewise guess.**

### AV2 — Parry and Riposte curves — **RECOMMEND**
Reuse the IDENTICAL curve (same shape AND same values as AV1's Dodge curve) fed with Dexterity instead of
Agility, for both Parry and Riposte, as the first-pass implementation. The design doc explicitly hasn't
differentiated these three yet ("flagged as tuning parameters... will be differentiated through playtesting")
— using identical curves is the simplest honest placeholder. Note the three checks are still independently
rolled in the waterfall (Riposte→Parry→Dodge), so even with identical per-check curves the COMPOUND avoidance
chance is meaningfully higher than any single check alone (roughly `1 - (1-p)³` for a defender with equal
Agility/Dexterity, before circumstance filtering).

### AV3 — Parry circumstance filter — **RECOMMEND**
A `bool isParryable` per attack (not a full `AttackType` enum — the design doc's own examples reduce to a
binary: "a lion bite cannot be parried, a sword swing can"). Player weapon auto-attack → always parryable.
`MobDefinition` gains `attackIsParryable` (bool, default true), authored per-mob in the Mob Editor (a "beast"
mob author sets it false) — same authoring posture as 5.1.1's HR5 mob fields, same migration batch if
convenient (or the next one after HR5's). If the filter fails, skip straight to the Dodge check.

### AV4 — Riposte counter-attack — **RECOMMEND**
On Riposte success: incoming attack resolves as Miss, then immediately fire a counter attack against the
original attacker using 5.1.3's Step 3 damage code only (no Step 2 avoidance check on the counter, no Step 4
mitigation, per design doc §3.5) at a reduced multiplier — recommend 50% of a normal Solid-Hit-tier result as
a placeholder (the doc doesn't give a number). Implemented as a direct synchronous call within the same
swing-resolution method for this pass, not a separate queued/animated action — a distinct riposte
animation/RPC is visual polish, not blocking the math.

## Done when

that scale with the defender's Agility/Dexterity per the approximated curve; a beast-type mob's attack
correctly skips the Parry check; a successful Riposte both negates the incoming hit AND fires a reduced-
damage counter attack against the original attacker.
