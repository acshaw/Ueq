# 3.1.1 — Client Screen-Flow Shell + Transitions

**Status:** 🟢 Approved (SF1–SF7) — implemented (code, 2026-07-04); pending in-editor verification.
**Parent:** 3.1 (new-player onboarding vertical). **Foundation** — 3.1.2/3.1.3/3.1.6/3.1.7 plug into this.

## Why

The client front-end is IMGUI (`LoginUI`, `CharacterSelectUI`) that **snaps** between states derived
implicitly from Mirror connection/localPlayer flags. The onboarding vertical needs a proper **screen
manager** that drives Title → Login/Register → Character Select → In-World with **fade transitions**, and a
uGUI home for the styled screens (this delivers the login/select uGUI conversion **deferred in 1.7, O5**).
3.1.1 builds the *framework + fades + functional uGUI parity*; the individual screens get their **visual**
polish in 3.1.2 (title), 3.1.3 (login/register), 3.1.6 (char select + 3D preview), 3.1.7 (camp/logout).

## Current flow (grounded)

- `LoginUI` (IMGUI, on the NetworkManager GO) — pre-connect: address + username/password + Login / Register
  / Host / Server Only; shows `AccountAuthenticator.LastClientMessage`. Hidden once `NetworkServer.active ||
  NetworkClient.active`.
- `CharacterSelectUI` (IMGUI, NM GO) — shown when `NetworkClient.connection.isAuthenticated &&
  localPlayer == null`. Roster + create form over Mirror messages (`CharacterListRequest`/`…Message`,
  `EnterWorldMessage`, `CreateCharacterMessage`, `DeleteCharacterMessage`, `CharacterActionResult`).
  Re-requests the roster when `localPlayer` goes away (camp return).
- `GameNetworkHUD` (IMGUI) — post-connect status + Stop.
- `UIManager` — additively loads `UI.unity` (the in-world HUD) at startup, persists across zones.
- `CampController` — camp countdown → `CampMessage` → server despawns → `localPlayer == null` → select.

**Derived screen = f(connection state):** no server/client → Title/Login; authenticated + no localPlayer →
Character Select; localPlayer present → In-World. The shell formalizes this into an explicit state machine
with transitions.

## Decisions

- **SF1 — Screen manager.** Add a `UIScreenManager` (singleton, lives in `UI.unity`) that owns a
  `ClientScreen` enum { `Title`, `Login`, `Register`, `CharacterSelect`, `Connecting`, `InWorld` }, exposes
  `Show(screen)`, and each frame computes the **target** screen from Mirror state (`NetworkClient.active` /
  `connection.isAuthenticated` / `localPlayer`); when target ≠ current it runs a transition. *Recommend.*
- **SF2 — Screens live in `UI.unity`.** The menu screens are uGUI panels under a `MenuCanvas` in the
  already-loaded additive UI scene (the HUD panels are the in-world screen). One scene, manager toggles
  visibility. *Recommend* (no new scene; reuses the 1.7 additive-UI infrastructure).
- **SF3 — Retire the IMGUI front-end.** Replace `LoginUI` + `CharacterSelectUI` with uGUI panels +
  controllers that **reuse the same Mirror messages + `AccountAuthenticator` hooks** (no server/protocol
  change). Fold `GameNetworkHUD`'s Stop into a shell "Disconnect/Quit". *Recommend* — this is the O5
  conversion.
- **SF4 — Fade transitions.** A full-screen `ScreenFader` (`CanvasGroup` overlay, top sort order):
  `fade-out (α→1) → swap active panel → fade-in (α→0)`, configurable duration (~0.25–0.4s). All screen
  changes route through it. *Recommend.*
- **SF5 — State derivation = poll.** Poll Mirror state each frame (matches the existing UIs) and transition
  on change; no new events/protocol. Guard against re-triggering mid-transition. *Recommend* (simplest,
  robust to reconnect/host-restart which the current UIs already handle by resetting).
- **SF6 — Scope: framework + functional parity, not styling.** 3.1.1 ships the manager + fader + **minimal,
  unstyled uGUI** Login and Character-Select panels at functional parity with today (all current buttons/
  flows work), so the flow + fades are real end-to-end. **Visual** design is 3.1.2/3.1.3/3.1.6/3.1.7.
  *Recommend* — keeps this piece the foundation, not a boil-the-ocean UI project.
- **SF7 — Title as a stub (APPROVED), built for trivial art-swap.** Include `Title` in the enum and wire it
  as the pre-connect entry (Title → Login). The stub `TitlePanel` = a **full-screen background `Image`
  (stretch-anchored)** with a flat color/gradient placeholder + a **title/logo `Image` slot** + Play/Quit
  buttons anchored in a centered "safe area". Both the background and logo are **serialized `Sprite` fields**
  on `TitlePanel`, so stylizing (3.1.2) is: assign a sprite (or overwrite the file at the known path) — **no
  code, no relayout.**

  **Title art hand-off contract** (what the user provides for 3.1.2):
  - **Background:** one image, **16:9**, **≥ 1920×1080** (ideally 2560×1440+ for crisp large displays),
    PNG (or JPG for a photographic screenshot). Keep the focal content **centered** — the background is set
    to **cover/crop** (never stretch), so ultrawide/narrow screens crop the edges; anything important must
    sit in the middle safe area. Drop at `Assets/UI/Title/TitleBackground.png`.
  - **Logo (optional):** transparent PNG, centered composition, e.g. ≤ 1024 tall. Drop at
    `Assets/UI/Title/TitleLogo.png`. If omitted, the panel falls back to styled text.
  - **Midjourney:** generate with `--ar 16:9`, upscale, export PNG, keep the composition centered.
  - **In-game screenshot:** capture at high res (a `Tools/Capture Title Screenshot` helper using
    `ScreenCapture.CaptureScreenshot(path, supersize)` can grab a 2×–4× shot of Creslin's Field / Trellis —
    offer to add it).
  - **Unity import:** Texture Type = **Sprite (2D and UI)**, Max Size **2048** (or 4096 for the background),
    Compression to taste. The panel uses the sprite on a stretch-anchored `Image` with
    `preserveAspect` off + a parent mask, or a cover-fit script — either way art fills the screen without
    distortion.

## Scope / files

**New (client, `Assets/Scripts/UI/Screens/`):**
- `UIScreenManager.cs` — the state machine + target-derivation + `Show()`.
- `ScreenFader.cs` — CanvasGroup fade in/out coroutine.
- `ScreenPanel.cs` (small base) — `OnShow()/OnHide()` for panels.
- `LoginPanel.cs`, `RegisterPanel.cs`, `CharacterSelectPanel.cs`, `TitlePanel.cs` — controllers binding the
  uGUI widgets to the existing Mirror messages / `AccountAuthenticator` fields.

**Editor tooling:** extend the UI-scene builder (`Tools/Build UI Scene`) to author `MenuCanvas` + the panels
+ the fader (procedural for now, matching how the HUD is built; real art/layout comes in the styling
sub-items). Or hand-author in `UI.unity` — reviewer's call (SF-tooling).

**Modified:** `UIManager` (ensure `UIScreenManager` exists), remove `LoginUI` / `CharacterSelectUI` /
`GameNetworkHUD` from the NM GO in `SceneSetup` (replaced by the shell). No server/`CharacterSelectController`
change — same messages.

**No** protocol/schema/migration change.

## Test plan (in-editor + MPPM)

1. **Cold start** → Title (or Login) fades in; enter creds → Register/Login → fades to Character Select.
2. **Create + enter** → fades to In-World (HUD visible), no snap.
3. **Camp** → fades back to Character Select; roster refreshed.
4. **Delete / create / multi-character** parity with the old IMGUI flow.
5. **Error paths** — wrong password / duplicate / already-online show in the uGUI (from
   `AccountAuthenticator.LastClientMessage`).
6. **Host + Server Only** entry points still work (fold into Title/Login).
7. **Reconnect / host-restart** in one session → shell resets to the pre-connect screen cleanly.
8. MPPM: two clients each drive their own shell independently.

## Risks

- **Transition vs. Mirror timing** — a fade must not swallow a state change (e.g., localPlayer arriving
  mid-fade). Mitigation: recompute target after each transition completes; keep transitions short.
- **Host superimposition** — Server Only / Host entry points must still be reachable from the shell (dev
  ergonomics) — keep them on Title/Login.
- Procedural uGUI is verbose; SF6 keeps it minimal so the styling sub-items own the real layout.

## Implementation log

**2026-07-04 — implemented (code only; pending in-editor verification).** Built as **runtime-constructed
uGUI** (self-contained scripts spawned at startup) rather than an editor scene-builder — lowest risk given
it couldn't be verified in-editor, and it keeps the change **purely additive** (no `SceneSetup`/NM-GO/zone
re-wiring, no `Setup All` needed). New (`Assets/Scripts/UI/Screens/`):
- `ClientScreen` enum + `ScreenPanel` base (`Init`/`Build`/`OnShow`/`OnHide`).
- `UIScreenManager` — singleton; builds a menu `Canvas` (sort 100, above HUD) + panels + fader; `Update`
  derives the target screen from Mirror state (`localPlayer` → InWorld; authenticated → CharacterSelect;
  client active → Connecting; else the nav'd pre-connect screen) and runs a faded transition on change;
  centralizes the auth glue (`Connect`/`HostAsDev`/`StartServerOnly`, reusing `AccountAuthenticator`
  fields + `LastClientMessage`); **disables the IMGUI `LoginUI`/`CharacterSelectUI` at runtime** (SF3) so
  they don't double-render (kept as files; `GameNetworkHUD` dev Stop left alone).
- `ScreenFader` — black `CanvasGroup` overlay, fade-out → swap → fade-in (unscaled time).
- `MenuUI` — TMP + legacy `Button`/`Image` factory matching the project's HUD builder.
- `TitlePanel` (SF7 stub; background/logo from `Resources/UI/Title/…`), `LoginPanel`, `RegisterPanel`,
  `ConnectingPanel`, `CharacterSelectPanel` (uGUI port of the IMGUI select/create, **same Mirror
  messages**; race/class are cycle buttons for now — styled picker + 3D preview is 3.1.6).
- `UIManager.Awake` now calls `UIScreenManager.EnsureExists()` (client-only; skipped in batch mode).

Notes / knowns: the shell relies on the **EventSystem in `UI.unity`** (loaded by `UIManager`) — no new
EventSystem created, to avoid duplicates. Title background is stretched (not cover-fit) in the stub — proper
cover-fit + real art is 3.1.2. `SceneSetup` still attaches the IMGUI components on fresh setups (disabled by
the shell) — removing them from the builder + deleting the files is a later cleanup once the shell is proven.
**Not compiled in-editor** — compile-correct by inspection (message/auth APIs mirrored from the retired
`LoginUI`/`CharacterSelectUI`); needs an in-editor pass + likely minor layout iteration.
