### Verification follow-ups (2026-07-05)
First in-editor pass: sit animation confirmed syncing across two MPPM clients (Cleric + Warrior). Two fixes:
- **Free-look while seated** — the body was rotating with the camera when looking around (RMB). Fixed so a
  seated player's **body stays frozen** while the camera free-looks: `NetworkedPlayer.ApplyLook` offsets the
  camera holder's yaw by `(_yaw − bodyYaw)` instead of driving the body, and `CmdSendInput` skips writing the
  body yaw while seated (so observers also see it stationary). Standing resumes body=`_yaw` with the holder
  offset returning to 0, so the view doesn't jump — the body turns to face the look direction on standing.
- **Camp gate (3.1.8 CP6) pulled forward** — `/camp` was allowed while standing. `CampController.RequestCamp`
  now refuses ("You must be sitting to camp.") unless `PlayerSitting.IsSitting`, and the countdown cancels
  ("you stood up.") if the player stands mid-camp. Client-side; a server-side re-check in
  `CharacterSelectController.OnCamp` remains available as optional hardening (3.1.8).
- **Camera height ease** — the camera holder now eases down `sitCameraDrop` (0.85m, serialized) when seated
  and back up when standing (`ApplyLook`, local player), so the sit/stand height change is felt. The standing
  height is captured on the first frame; tune `sitCameraDrop`/`sitCameraLerp` in the inspector to taste.

## Why
EQ-style resting: a player can toggle a seated state to recover faster, and getting hit (or moving) snaps
them back up. It's a small, reusable player state with **three consumers**, two of them already designed:
- **Regen boost** — the HP/mana-regen design has always specified *"1/tick standing, 2/tick sitting (sitting
  deferred until a sitting state exists)"*. `PlayerRegen` is a no-op stub for the seated case today. This
  finally lights it up.
- **Camp gate** — 3.1.8 refuses `/camp` unless the player is sitting.
- **Future** — meditate / mana-med, "can't act while seated" rules, ambient flavor.

## Scope
A server-authoritative, synced sitting state; `/sit` command + hotbar key `0` to toggle; a looping seated
animation from `sitting.fbx`; auto-stand on damage and on movement; the deferred 2/tick regen. The camp
precondition itself is **3.1.8** (this item just exposes `IsSitting`).

Out of scope: blocking melee/casting while seated (EQ does; MVP leaves actions unrestricted — noted as
future), meditate/mana-specific rules, any UI beyond the animation + existing chat.

## Current state (grounding)
- `CombatState` (`Assets/Scripts/Combat/`) is the exact pattern to mirror: a small `NetworkBehaviour` with a
  `[SyncVar(hook)]` flag, a `[Server]` setter, an `InCombat` getter, and a client event.
- `Health.TakeDamage` already reaches for sibling components on damage: `GetComponent<CombatState>()?.MarkCombat()`
  (`Health.cs:85`). Auto-stand-on-hit hooks the same spot.
- `PlayerAutoAttack` polls `Keyboard.current.digit1Key` for the key-1 autoattack toggle — the precedent for a
  key-`0` sit toggle (poll on the local player only).
- `NetworkedPlayer.CmdSendInput` is the server-side per-frame input entry (move/yaw/sprint/jump) — where a
  "moved while seated → stand" check belongs.
- `PlayerRegen.Tick` heals a flat 1 HP + 1 mana every 6s; it has no seated branch yet.
- `PlayerAnimatorSetup` builds the locomotion controller and adds one-shot states via `AddTriggeredState`
  (Attack/Kick/Cast, Any-State→state on a trigger). Sitting is a **held** state (bool), so it needs a
  different transition shape (Locomotion↔Sit on a `Sitting` bool), not a trigger.
- `PlayerAnimator` (on the model child) drives the Animator; `PlayerModel` can rebuild that child on a
  race/class change, so anything feeding the Animator must re-resolve after a rebuild (the established poll
  pattern).
- User added `sitting.fbx` (must be imported **Humanoid + Loop Time on** — like the other clips).

## Decisions

### SI1 — State component — **recommend: new `PlayerSitting : NetworkBehaviour`, mirroring `CombatState`**
`[SyncVar(hook)] bool _sitting`, `public bool IsSitting => _sitting`, `[Server] ServerSetSit(bool)` /
`ServerStand()`, `[Command] CmdToggleSit()`. Added to the Player prefab via `SceneSetup` patch. Synced so
every client renders the seated pose for local + remote players (same as `CombatState`/movement).

### SI2 — Toggle inputs — **recommend: `/sit` command + hotbar key `0`, both → `CmdToggleSit`**
`ChatUI.TryHandleLocalCommand` gains `/sit` (→ `LocalPlayer.Current.GetComponent<PlayerSitting>()?.CmdToggleSit()`),
alongside the existing `/camp`/`/unstuck`. `PlayerSitting` polls `Keyboard.current.digit0Key` on the local
player (suppressed while chat is open, like the other hotkeys) → `CmdToggleSit`. Add `/stand` as an explicit
stand (idempotent) for clarity. Key `0` is a stand-in slot; a real hotbar rebind can come later.

### SI3 — Auto-stand — **recommend: stand on damage AND on movement, server-authoritative**
(a) **Damage:** in `Health.TakeDamage`, next to the `MarkCombat()` call, add
`GetComponent<PlayerSitting>()?.ServerStand()` — the target stands the instant it's hit (mirrors the existing
sibling-component pattern; no event wiring needed). (b) **Movement:** in `NetworkedPlayer.CmdSendInput`, if
seated and the move vector exceeds a small threshold, `ServerStand()`. Both are server-side so they're
authoritative and reach all observers via the SyncVar.

### SI4 — Animation — **recommend: a bool-driven Sit state added to the locomotion controller**
Extend `PlayerAnimatorSetup` to (1) add a `Sitting` bool parameter and (2) build a **looping** Sit state from
`sitting.fbx` (matched by the `sit` filename keyword, like `cast`/`kick`), with Locomotion→Sit when
`Sitting` is true and Sit→Locomotion when false (a new `AddBoolState` helper — the one-shot `AddTriggeredState`
doesn't fit a held pose). `PlayerSitting` drives the `Sitting` bool client-side from `_sitting`, re-resolving
the Animator each tick so it survives a `PlayerModel` body rebuild. Requires re-running
`Tools/Build Player Locomotion Controller` after importing the clip.

### SI5 — Regen boost — **recommend: `PlayerRegen` heals 2/tick when seated (the deferred design)**
`PlayerRegen.Tick` reads `GetComponent<PlayerSitting>()?.IsSitting`: seated → heal 2 HP + 2 mana, standing →
1 + 1 (unchanged). This is the long-deferred "2/tick sitting" finally wired. Tick cadence stays 6s.

### SI6 — Constraints — **recommend: sit anytime; hit/move stands you; actions stay unrestricted (MVP)**
No gate on entering the seated state (you can sit in combat — it's just risky, since the next hit stands you,
SI3). Sitting does **not** block abilities/melee for MVP (EQ blocks melee while seated — noted as a future
refinement once it matters). Moving stands you (SI3b), so you can't slide around seated.
