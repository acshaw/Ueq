# 3.1.8 — Camp / Logout Polish

**Status:** 🟡 Draft — awaiting review. CP1/CP3/CP5 carry recommendations; CP2 (chat-only, no overlay) and
CP4 (timeout fallback) decided 2026-07-05. **Depends on 3.1.7 (sitting): `/camp` is gated on sitting — see CP6.**

## Why
Leaving the world is the one onboarding transition that still snaps. The camp flow (`/camp` or the dev HUD
button → 10s countdown → `CampMessage`) despawns the player **first**, and only then does the shell notice
`localPlayer` went null and start its fade. So for a beat you see the player pop out and the camera drop
(the "No cameras rendering" gap) before black covers it. The fade back to Character Select should hide the
teardown entirely — the same "fades, not snaps" bar the rest of 3.1 meets. (Logout from Character Select →
Title is already a clean menu→menu fade; see CP3.)

## Scope
1. **Cover the camp teardown with a fade** — fade to black *before* the despawn, hold through it, reveal on
   Character Select. No visible player-pop / camera gap.
2. **Sitting gate** — `/camp` refuses unless the player is sitting (3.1.7). Countdown stays chat-only (CP2).
3. **Tidy teardown** — confirm chat clear / HUD unbind / coroutine + fader state all reset cleanly on the way
   out, and that a rejected camp doesn't strand the screen in black.

Out of scope: an in-world pause/Esc menu (camp still triggers via `/camp` + dev HUD); zone/bind changes;
anything server-authoritative beyond what camp already does.

## Current state (grounding)
- `CampController` (on the NetworkManager GO) runs the client countdown, cancels on move/combat, and on
  completion sends `CampMessage`. Combat is checked client-side before + during the countdown.
- Server `CharacterSelectController.OnCamp` re-checks combat authoritatively, `Save()`s, clears
  `SelectedCharacterId`, then `NetworkServer.RemovePlayerForConnection(conn, Destroy)`. On reject it only
  sends a System chat line — **no structured result message**.
- `UIScreenManager.Update` derives the target screen from Mirror state; when `localPlayer` becomes null it
  computes `CharacterSelect` and runs `ShowRoutine` → `ScreenFader.Transition` (fade→swap→fade). The fade
  therefore starts *after* the despawn — the snap.
- `ScreenFader.Transition(swap)` = fade to black → swap → fade back; `FadeTo` is private; `Duration = 0.28`.
- Logout: Character Select "Log Out" → `Manager.Disconnect()` → `StopClient/StopHost` → target flips to
  Title → shell fades (menu→menu, no world). Already smooth.

## Decisions

### CP1 — Camp exit fade — **recommend: a scripted "exit" transition in the shell that fades before the despawn**
Add `UIScreenManager.ExitWorld(System.Action teardown)`: set the transition guard, **fade to black**, invoke
`teardown` (which sends `CampMessage`) under black, wait until Mirror resolves out of `InWorld`
(`localPlayer` null), `SwapTo` the resolved screen while black, then **fade in**. `CampController`, on
countdown completion, calls `UIScreenManager.Instance.ExitWorld(() => NetworkClient.Send(new CampMessage()))`
instead of sending directly. The existing `_transitioning` guard stops `Update` from firing a competing
transition when `localPlayer` goes null. Requires exposing a fader primitive (make `FadeTo` public, or add
`Cover()`/`Reveal()`), which also keeps the fader the single owner of the alpha.

### CP2 — Countdown presentation — **DECIDED (2026-07-05): chat-only, no overlay.**
The existing per-second chat countdown ("Camping… N", cancel lines) stays as-is — no on-screen overlay. Keeps
the change focused on the fade (CP1).

### CP3 — Logout paths — **recommend: no change (already smooth), just cover in the test plan**
Character Select → Log Out → Title is menu→menu and already fades via the shell. The only in-world exit is
camp (CP1). Confirm both in testing; no code.

### CP4 — Rejected-camp safety — **DECIDED (2026-07-05): timeout fallback (reveal in-world); explicit result message deferred**
Because CP1 fades optimistically before the server confirms, a server-side reject (the rare combat sync-race
— client thinks not-in-combat, server disagrees) would otherwise strand the screen black. Guard `ExitWorld`'s
wait with a timeout (~2s): if `localPlayer` is still non-null when it elapses, the camp was refused → reveal
back to In-World (the server's "can't camp" chat line already shows). This corner case is near-impossible for
a legit client (the countdown already cancels on combat), so a structured `CampResult{ok,reason}` message to
abort the fade instantly is noted as optional hardening, not built now.

### CP5 — Teardown hygiene — **recommend: verify + small fixes only**
Confirm on camp: the countdown coroutine is cleared (it is), chat clears on the switch + MOTD reprints
(1.6.1), the HUD panels unbind via `LocalPlayer.Despawned`, and the fader ends at alpha 0 with
`blocksRaycasts` false. Fix anything that lingers; no redesign expected.

### CP6 — Sitting gate (depends on 3.1.7) — **DONE in 3.1.7 (client-side); optional server re-check remains**
`CampController.RequestCamp` refuses ("You must be sitting to camp.") unless `PlayerSitting.IsSitting`, and the
countdown cancels ("you stood up.") if the player stands mid-camp — **implemented during 3.1.7 verification**
(the user expected the gate as part of sitting). No auto-sit. Only optional hardening remains for 3.1.8: an
authoritative re-check in `CharacterSelectController.OnCamp` (mirrors its existing combat re-check) so a
hacked client can't bypass. Low priority — camping is benign.

## Build / test plan
1. **Exit fade (CP1 + CP4).** Expose the fader primitive; add `ExitWorld`; route `CampController` through it.
   *Test:* `/camp` out of combat → countdown → screen fades to black with the player still visible, then
   reveals on Character Select — no player-pop or camera gap. Force the reject path (camp the instant combat
   ends) → after the timeout it reveals back in-world with the "can't camp" line (no stuck black).
2. **Sitting gate (CP6).** Add the `PlayerSitting.IsSitting` precondition to `RequestCamp`. *Test:* `/camp`
   while standing → refused ("You must be sitting to camp."); `/sit` then `/camp` → countdown proceeds.
3. **Regression (CP3/CP5).** Logout from Character Select → Title still fades; relog after camp reconstructs
   the character; chat clears + MOTD; no lingering fader/HUD state. Verify camp as **host** and as a remote
   MPPM client.

## Done when
Camp (from a seated player) fades out → despawns under black → fades in on Character Select with no visible
snap or camera gap; a refused camp recovers cleanly; standing `/camp` is refused; logout→Title still fades;
verified host + remote client. Then mark roadmap 3.1.8 ✅ → 3.1.9.

## Deferred / backlog seeds
- Structured `CampResult` message (instant reject abort) instead of the timeout fallback (CP4).
- In-world pause/Esc menu with an explicit Camp/Logout button (camp is `/camp` + dev HUD for now).
