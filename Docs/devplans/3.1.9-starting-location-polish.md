# 3.1.9 — Starting-Zone Shaping + Light Dressing

**Status:** 🟠 Reshaped + implementing 2026-07-05. **Scope grew** from "light dressing" to also *shaping* the
starter zone, after in-editor work showed two foundational problems (see Why). Final sub-item of the 3.1
onboarding vertical; editor-heavy, code-light.

## Why (reshaped 2026-07-05)
Dressing the spawn area surfaced two problems that dressing can't fix:
1. **Hilly playable core.** Hills were added "for texture" across the whole map. But props/buildings/trails on
   slopes float or sink and cut cliff-edge seams, the navmesh gets chopped, and the CharacterController slope
   limit starts blocking movement — this fights *both* the tools and hand-placement. The design doc already
   wants the opposite: Creslin's Field is "a large **open field**" bounded by ocean (W), hills→mountains (E),
   treeline (N), road (S). **Fix: flat playable core, hills pushed to the perimeter as boundary/backdrop.**
2. **Zone far too small.** Walk speed is **3 u/s** (Player prefab `moveSpeed`; sprint **5**) — confirmed by
   in-editor timings (a ~315u path walked in ~1:45; a ~825u road *run* in ~2:45). The dressed area was ~110u
   and the Thornwood **portal sat ~15u north of spawn**. **Fix (user's target ≈ 5-min run per zone): a big
   ~1500×1500u field**, portal at the far north (~1380u from spawn ≈ 5 min run / 8 min walk). Safe against the
   5000u zone-offset spacing (half-width 750 « 5000; float precision fine at ≤ ~11k u). Size is a constant in
   `CreslinsFieldSetup`.

Get the foundation right (flat + sized + portal-north), then the village + trails drop in easily on flat
ground, and content spreads along a real zone. Full population is still **3.6**.

## Scope
1. **Shape** — a flat ~1500×1500u walkable field; Thornwood portal (+ its return entry) moved to the far north
   (~1380u from spawn); a light perimeter frame (trees, east rocks) reading as the zone edges. (Terrain tool.)
2. **Dress** — the Trellis-village-edge hub near spawn + optional dirt trails, now on flat ground (existing
   hub/trail tools, which work well once the core is flat).

Out of scope: zone population (NPCs/mobs/spawns/quests), themed edges (real ocean/mountain art), the other two
zones — all **3.6**.

## Current state (grounding)
- Creslin's Field = base `SampleScene` (zone `creslins_field`, offset 0). Spawn = a `NetworkStartPosition`
  ~(0,·,-5); a `ZonePortal{targetZoneId="thornwood"}` ~15u north; a `ZoneEntry{entryId="default"}` at spawn +
  (likely) a non-default return entry near the portal. Portal/entry are plain MonoBehaviours positioned by
  transform — safe to reposition from an editor script.
- Walkable `Ground` = a plane holding the `NavMeshSurface` (bakes off its collider, `m_UseGeometry =
  PhysicsColliders`), renderer hidden, grass tiles on top. Resizing its scale resizes the walkable area +
  navmesh source.
- Scene already has a `SyntyTerrain` grassland (110u) + the user's hand-placed hills scattered in the core.
- Movement/collision run on **physics colliders**, not the navmesh — so the player experience only needs the
  flat ground + building colliders; the navmesh only matters for mob pathing (rebake before 3.6 mobs).

## Decisions

### SL1 — Field size — **DECIDED: ~1500×1500u flat field; portal ~1380u north of spawn**
User target ≈ 5-min *run* per zone → ~1500u (5 min run / 8 min walk to cross). Set by constants at the top of
`CreslinsFieldSetup` (`FieldWidth`/`FieldLength`/`PortalOffsetZ`) — trivially resized. Grass tiles + perimeter
auto-scale so the huge field doesn't spawn thousands of objects (`MinTileStep`/`TreeSpacing`). *Consideration:
an 8-min-walk empty starting field can feel like a slog until 3.6 populates it; narrowing E-W (it's a N-S
journey) or shrinking is easy if it plays big.*

### SL2 — Flat core, hills to the perimeter — **DECIDED**
The playable core is flat (y=0). Hills/rocks/trees ring the edges as boundary + backdrop (ocean W / hills E /
treeline N per the doc). The user's old scattered core hills are deleted by hand (the tool can't identify
arbitrary hand-placed objects; it flattens the ground *under* them and logs the cleanup).

### SL3 — Tooling — **DECIDED: a `Tools/Zones/Reshape Creslins Field` builder, then hand-tune**
Reproducible builder: resize the flat `Ground`, re-tile grass over the full field, ring a light perimeter,
and reposition the Thornwood portal + its return entry to the north edge. Non-destructive to user content
except: resizes `Ground`, clears its own `CreslinsField` root + the redundant `SyntyTerrain` grassland (known
tool-generated name), and moves the portal/entry. Then the hub + trail tools run on the flat core.

### SL4 — Portal / entry reposition — **DECIDED: move both to the north edge, keep `default` + spawn put**
Move `ZonePortal{thornwood}` to ~(spawn.x, ·, spawn.z+240) and the nearby non-`default` `ZoneEntry` (the
from-Thornwood arrival) just south of it; leave `entryId="default"` and the `NetworkStartPosition` at spawn.
The server `ZoneManager` reads portal/entry positions at runtime, so moving the transforms is sufficient —
**but this is the delicate bit: verify the round-trip creslins⇄thornwood still works after.**

### SL5 — NavMesh + colliders — **DECIDED: flat ground = clean navmesh; rebake before mobs**
Flat ground → the navmesh bakes cleanly off the plane collider; perimeter trees keep colliders (carve the
boundary); grass/foliage stripped + nav-excluded. Rebake (`Tools/Terrain/Rebake NavMesh`) after shaping;
not player-blocking, only mob pathing (3.6).

## Build / test plan
1. **Shape** (`Reshape Creslins Field`): flat ~1500×1500 ground, grass re-tiled, perimeter frame, portal+entry
   moved north. *Then* delete the old hand-placed core hills + old `SyntyTerrain` (log guides this).
2. **Re-dress on flat ground:** re-run `Build Trellis Starter Hub` (buildings now sit flush) and, if wanted,
   `Build Path Along Children` (trails now lay flat). **Fill the field** with the new tooling: `Scatter Props`
   (density-slider vegetation, layer passes), and `POI/Build Undead Ruins` + `POI/Build Lake` (curated
   landmarks anchored to a selected empty). All conform to the ground + accumulate under managed roots.
3. **Rebake** the navmesh; **save** the scene.
4. **Playtest:** fresh spawn reads as an intentional village edge; walk **north across the field to the portal
   — should take ~3–5 min at walk speed**; transition to Thornwood and **back** works (SL4 round-trip); no
   sinking / floating / blocked spawn. Host + a remote MPPM client.

## Done when
Creslin's Field is a flat, ~1500u zone (≈ 5-min run to cross) with the Thornwood portal at the far north, a dressed
Trellis hub near spawn, and a working creslins⇄thornwood round-trip. Full population = 3.6. Then mark 3.1.9 ✅
→ **3.1 onboarding vertical complete.**
