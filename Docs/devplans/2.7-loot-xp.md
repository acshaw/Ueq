## Goal

Migrate the last two cluster content types to Postgres + web editors:

1. **Loot tables** — weighted item pool + drop-count distribution + coin tiers, rolled when a mob dies.
2. **XP thresholds** — the 50-level XP curve the leveling math reads.

Both are nearly pure plumbing because the consumers are already wired:
- `Corpse.cs:25` already rolls `mob.lootTable`; `MobRegistry.Build` already carries `lootTableId` and sets `def.lootTable = null` *"resolved at 2.7"*. Populating a `LootRegistry` flips drops on.
- `PlayerExperience` already reads a static `XpTableDefinition` (today `Resources.Load("XpTable")`); swapping its source to a DB-built table is the whole change.

Completing 2.7 unlocks the cluster's final test: a **web-authored hostile mob that drops web-authored loot** (and, with 2.6, aggroes on faction). After this, only quests (2.8), abilities (2.9), and races/classes (2.10) remain to migrate.

## What these are, in data

### Loot table (mirrors `LootTable.cs` 1:1)
Three weighted child lists + a header:
- **items** — `(item_id, weight)`; references items (2.2).
- **drop_counts** — `(count, weight)`; how many item rolls happen (e.g. 0×50, 1×30, 2×15, 3×5).
- **coin_tiers** — `(min_copper, max_copper, weight)`; a weighted coin drop (fixed when min==max).

`Roll()` picks a drop count, rolls that many items from the item pool, and one coin tier. All server-side.

### XP table (mirrors `XpTableDefinition.cs`)
A single shared 50-row curve: `xp_to_next` per level. `PlayerExperience` derives level / total-to-reach / death-loss from it; `MaxLevel = row count`.

### Faithful seed data (from the existing assets)
- **Giant Rat Loot Table** (`Giant Rat Loot Table.asset`): items `rat_paw` / `rat_ear` / `rat_whisker` (weight 1 each — *verify the 3 guids `c68d1bd5…`/`44c22bc6…`/`33da7377…` map to those item_ids at implementation*); drop_counts `0:50, 1:30, 2:15, 3:5`; coin_tiers `0c:21, 1c:5, 2c:4, 3c:3, 4c:2, 5c:1`.
- **XP table** (`Resources/XpTable.asset` / `XpTableDefinition.DefaultValues`): the 50 values `1_000 … 10_291_400`.

## Schema — `0014_loot_xp.sql` (schema only; seeded idempotently by `DatabaseSeeder`)

```sql
CREATE TABLE IF NOT EXISTS loot_tables (
    loot_table_id TEXT PRIMARY KEY,        -- "Giant Rat Loot Table"
    display_name  TEXT NOT NULL DEFAULT '',
    updated_at    TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS loot_table_items (
    id            BIGSERIAL PRIMARY KEY,
    loot_table_id TEXT NOT NULL REFERENCES loot_tables(loot_table_id) ON DELETE CASCADE,
    item_id       TEXT NOT NULL,           -- references items.item_id (soft ref)
    weight        INT  NOT NULL DEFAULT 1,
    sort_order    INT  NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS loot_table_drop_counts (
    id            BIGSERIAL PRIMARY KEY,
    loot_table_id TEXT NOT NULL REFERENCES loot_tables(loot_table_id) ON DELETE CASCADE,
    count         INT  NOT NULL DEFAULT 0,
    weight        INT  NOT NULL DEFAULT 1,
    sort_order    INT  NOT NULL DEFAULT 0
);

CREATE TABLE IF NOT EXISTS loot_table_coin_tiers (
    id            BIGSERIAL PRIMARY KEY,
    loot_table_id TEXT NOT NULL REFERENCES loot_tables(loot_table_id) ON DELETE CASCADE,
    min_copper    INT  NOT NULL DEFAULT 0,
    max_copper    INT  NOT NULL DEFAULT 0,
    weight        INT  NOT NULL DEFAULT 1,
    sort_order    INT  NOT NULL DEFAULT 0
);

-- Single shared XP curve — one row per level (DL2).
CREATE TABLE IF NOT EXISTS xp_levels (
    level       INT PRIMARY KEY,           -- 1..N
    xp_to_next  INT NOT NULL               -- XP to advance from `level` to `level+1`
);
```

## Unity (server-only)

- **`LootSnapshot`/`LootRepository`** — a bundled `LootTableSnapshot { id, displayName, List<(item_id,weight)>, List<(count,weight)>, List<(min,max,weight)> }`, loaded with the header-then-children pattern (`VendorInventoryRepository`/`ConversationRepository` shape).
- **`LootRegistry`** (new) — `LoadFrom(snapshots)` builds runtime `LootTable` instances (`ScriptableObject.CreateInstance`); each `ItemEntry.item = ItemRegistry.Get(item_id)` (so loot reaches items through the 2.2 registry, no SO refs). `Get(loot_table_id)`. Items must load first.
- **`XpRepository`** + a static source for `PlayerExperience` — build a runtime `XpTableDefinition` (`xpPerLevel` from `xp_levels` ordered by level). Add a static seam on `PlayerExperience` (e.g. `PlayerExperience.SetTable(def)` / a small `XpRegistry`) so the existing static `Table` prefers the DB table, falling back to `Resources.Load("XpTable")` then `DefaultValues`.
- **`MobRegistry.Build`** — change `def.lootTable = null` → `def.lootTable = LootRegistry.Get(s.LootTableId)`. (No other change; `Corpse` already rolls `mob.lootTable`.)
- **`ContentLoader.LoadAll`** — add a **loot step before mobs** (mobs resolve `lootTable` at build) and an **XP step** (order-independent). New order: items → vendors → conversations → factions → **loot** → mobs → **xp**. Log `[Content] Loaded N loot table(s)` and `[Content] Loaded N XP level(s)`.
- **`DatabaseSeeder`** — `SeedLootTables` (Giant Rat) + `SeedXpTable` (50 rows from `DefaultValues`), idempotent.

## API (.NET, mapping-only EF)

- `LootTable` entity + the three child entities + `LootTableDto` (flat: header + items[] + dropCounts[] + coinTiers[]); `LootTablesController` (nested CRUD by `loot_table_id`, replace-children on PUT, cascade on DELETE) — same shape as `FactionsController`.
- `XpLevel` entity + `XpController` `GET`/`PUT` over `xp_levels` (one ordered list, replace wholesale — like `ThresholdsController`).
- `ContentDbContext` DbSets + mappings.

## Angular

- **`XpEditor`** + `xp.service` — the single 50-row curve (level + xp_to_next), editable. Added to nav.

## Decisions (recommendations in **bold**)

- **DL1 — Loot child shape.** **Three child tables (items / drop_counts / coin_tiers)** mirroring the SO exactly. Keeps `LootTable.Roll()` byte-for-byte and the editor obvious.
- **DL2 — XP storage.** **One row per level (`xp_levels`), one shared curve.** Matches the Unity Race & Class Editor's per-level XP grid and is trivially editable. (Alternative — an int[] blob — is opaque to the web editor; rejected.)
- **DL3 — Retire the Resources/SO paths now?** **Yes, to a fallback.** Loot reaches items via `ItemRegistry`; `LootRegistry.Get` returns null → no drops if a mob references a missing table (logged). XP: `PlayerExperience` keeps `Resources("XpTable")` → `DefaultValues` as fallbacks when the DB table is absent (headless/no-DB). Don't delete `LootTable`/`XpTableDefinition` classes — they're the in-memory runtime types.
- **DL4 — Editors: separate or combined?** **Two nav entries, Loot and XP.** They're unrelated shapes; combining adds nothing. *(Note: the Unity Race & Class Editor's XP tab now edits the fallback asset only — the web XP editor is authoritative once the DB table exists; flag in CLAUDE.md, don't remove the Unity tab.)*
- **DL5 — Wire the mob loot dropdown now?** **Yes** — closes the last "(2.7)" placeholder in the Mob Editor, same as the faction dropdown in 2.6.

## Test plan

1. **API (curl vs Postgres):** loot-table nested CRUD (3 child lists replace on PUT, cascade on DELETE); XP GET/PUT.
2. **Load:** `Run Migrations` (0014) → `Seed Database` → host logs `[Content] Loaded 1 loot table(s)` + `[Content] Loaded 50 XP level(s)`; seeded mobs build with a non-null `lootTable`.
3. **Loot drop (the milestone):** kill a Giant-Rat-faction… i.e. a mob whose `loot_table_id = Giant Rat Loot Table` → loot the corpse → see rat parts + occasional copper at the seeded weights. Edit the table in the web app (add an item / change a weight) → restart host → confirm the change reflects in drops.
4. **XP curve:** confirm level-up thresholds match the table (kill XP → level math); edit a level's `xp_to_next` in the web app → restart host → confirm the new threshold applies. Sanity: `MaxLevel == 50`.

## Risks

- **Load order** — loot must load **before** mobs (`MobRegistry.Build` resolves `lootTable`), like factions. Items already load first (loot needs them for `ItemRegistry.Get`).
- **Item-id mapping in the seed** — verify the Giant Rat asset's 3 item guids really are `rat_paw`/`rat_ear`/`rat_whisker` before seeding (don't seed dangling item_ids).
- **XP static seam** — `PlayerExperience.Table` is a static cache; make sure the DB table is set before any leveling math runs (set it in the `ContentLoader` XP step, which runs at host start before play) and that the cache can't latch the Resources fallback first.
- **Empty/missing table** — a mob pointing at a non-existent loot table should drop nothing (and log once), not throw in `Corpse`.

## Done when

Loot tables and the XP curve are authored in the Angular app, stored in Postgres, and loaded at startup; a **web-authored mob drops web-authored loot**, and the **XP curve drives leveling from the DB**; the `Resources` loot/XP paths are retired to fallbacks; the Mob Editor picks a loot table from a dropdown. The NPC content cluster (2.3–2.7) is complete.
