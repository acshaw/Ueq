# 5.1.4 — Combat Pipeline: Mitigation

**Status:** ✅ Done — verified in-editor 2026-07-15. Ships exactly as scoped: a real no-op seam,
not a placeholder formula.

**Last of four sibling devplans** (see `5.1.1-hit-roll.md` for full numbering/build-order/scope notes — this
is built last, after 5.1.1/5.1.3/5.1.2, per the design doc's own recommendation). Grounded in
`docs/eventide_combat_pipeline.md` §5 ("Step 4 — Mitigation, NAMED — UNDEFINED").

## Grounding
Section 5 of the design doc is the least developed of the four steps — only design *principles* exist
(armor is the primary input; avoidance and mitigation are independently-capped, separate systems; a Crippling
hit through armor shouldn't one-shot; a Glancing hit against no armor should still hurt), no formula. The doc
is explicit: "Step 4 is the least developed part of the combat pipeline and requires a dedicated design
session before implementation," and §6.3 recommends shipping it as a zero-reduction stub initially specifically
so the rest of the pipeline (5.1.1–5.1.3) can be built and tested without waiting on it. There is currently no
armor/AC/mitigation field anywhere in the codebase (`ItemDefinition`, `CharacterStats`, `MobDefinition` all
confirmed clean via grep) — nothing to read yet, which is fine given the stub.

## Decisions

### MT1 — Ship as an explicit zero-op seam — **DECIDED, per the design doc's own recommended order**
`ApplyMitigation(rawDamage, defender) → finalDamage` returns `rawDamage` unchanged. A named function, not a
missing step — 5.1.1–5.1.3's `CombatResolver` calls it every time so the seam exists and is exercised, it
just doesn't reduce anything yet. This means the FULL pipeline (Hit → Avoidance → Damage → "Mitigation") is
wired end-to-end and shippable well before armor design happens, with zero restructuring needed once it does.

## Files touched (expected)
- **Edit** `Assets/Scripts/Combat/CombatResolver.cs` — add the `ApplyMitigation` seam as the final step,

## Done when
The combat resolver's public entry point runs all four named steps (Hit → Avoidance → Damage → Mitigation)
in sequence, with Mitigation confirmed as a no-op (final damage == raw damage from 5.1.3) — nothing more.
