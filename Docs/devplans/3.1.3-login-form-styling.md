## Why

3.1.2 delivered the title art + the inline form, but the form itself is still the raw `MenuUI` factory look:
sharp-cornered dark input boxes, placeholder-only labels, three stacked buttons of similar weight, and a bare
status line. It's functional and legible (scrim + dark field backgrounds) but reads as unstyled. 3.1.3 makes
the inline form feel intentional **without** re-introducing a heavy dialog card (that would undo the
art-forward feel we just built).

## Scope

- **In:** visual treatment of the inline **Login** and **Register** forms on the title — fields, labels,
  button hierarchy, status line, spacing, focus feedback. Reuse/extend shared `MenuUI` styling so the look is
  consistent (and Character Select inherits it later).
- **Out:** the title art/wordmark/menu (done in 3.1.2), Character Select redesign (**3.1.6**), any flow/auth
  change. Keep it art-forward — no return to a boxed dialog.

## Current state (grounding)

`TitlePanel.BuildLogin/BuildRegister` (`MenuPanels.cs`) build, into the 380px left column under the wordmark:
`MenuUI.Input` fields (Server/Username/Password) + `MenuUI.Button`s (Log In accent, Create Account, Back) +
a `MenuUI.Text` status line. `MenuUI.Input` = `TMP_DefaultControls.CreateInputField` tinted `FieldColor`
(sharp rect); `MenuUI.Button` now has hover/press color states (3.1.2) but sharp corners.

## Decisions

### L1 — Overall treatment — **recommend: stay art-forward (no dialog card), lift the form with polish not a box**
Keep the fields floating over the art on the left scrim. Improve legibility/structure with **field styling +
spacing + a small heading**, not an opaque panel. *(Optional, if it reads busy in-editor: a *very* faint
translucent strip behind just the field group — decided visually after first look.)*

### L2 — Rounded corners on fields + buttons — **recommend: yes, via a generated 9-slice sprite**
The single biggest lift. Add a `MenuUI` helper that generates a rounded-rect sprite (drawn into a `Texture2D`
with a corner radius + sprite border for 9-slice) and use it as the background sprite for inputs and buttons.
Rounds every button/field project-wide (buttons, fields, Character Select later) for a consistent, modern feel.
Low-risk, self-contained (same approach as the 3.1.2 gradient generator).

### L3 — Labels + mode heading — **recommend: small heading + keep placeholder labels**
Add a small mode heading above the fields (**"Sign In"** / **"Create Account"**) so the inline mode is clear.
Keep labels **inside** the fields as placeholders (cleaner, saves vertical space over the art) with a slightly
brighter placeholder color. *(Alt: labels above each field — more formal but taller; rejected for the inline look.)*

### L4 — Button hierarchy — **recommend: one primary + lighter secondaries**
**Log In / Register & Connect** stays the accent primary. Demote **Create Account** and **Back** to lighter,
lower-weight buttons (or text-link style) so the eye lands on the primary action. Reduces the "three equal
buttons" clutter.

### L5 — Focus feedback — **recommend: highlight the focused field**
Brighten the focused input's background/border (via the field's Selectable state colors, mirroring the button
states added in 3.1.2) so keyboard Tab-nav is visible. Cheap, and it makes the Tab/Enter nav feel deliberate.

### L6 — Server field — **recommend: de-emphasize (tuck it), default hidden for a "player" look**
A real player won't type a server address; it's a dev/localhost convenience. Options: (a) keep it but smaller /
below an "Advanced" toggle; (b) move server entry into the bottom-left **dev cluster** and default the client
to `localhost`; (c) leave as-is. Recommend **(b)** — cleanest player-facing login (Username/Password only),
server address stays a dev affordance. *(Cheap to change; decide now so the form layout is final.)*
