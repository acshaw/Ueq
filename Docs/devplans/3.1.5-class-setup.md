## Why

3.1.4 stood up the three classes as *bodies* and *identities*, but Wizard and Cleric are still **placeholder
ClassDefinitions** (stamped by the roster builder) with no abilities, and nothing yet makes the classes *play*
differently. 3.1.5 makes each class feel distinct at level 1: correct stats/HP/mana and **one working signature
ability each** (Warrior Kick, Wizard nuke, Cleric heal) with a real cast animation. Deliberately shallow — a
full kit + real combat depth is M4 (4.1/4.2). **Weapon props moved to 3.1.6** (aligned in the live preview).

## Scope

- **In:** finalize Warrior/Wizard/Cleric `ClassDefinition` stats + HP/mana formulas; author the two missing
  signature abilities (Wizard nuke, Cleric heal) + give Warrior's existing Kick a real effect; assign
  `startingAbilities` per class (auto-populates the hotbar); wire a shared **Cast** animation (Mixamo clip).
- **Out:** **weapon props (→ 3.1.6, aligned in the live preview)**; more than one ability per class;
  cooldown-kit balance; friendly/group heal targeting (self-heal only until grouping); the char-select 3D
  preview (**3.1.6**); combat-system depth (**M4**). No new ability *mechanic* is needed —
  `DamageEffect`/`HealEffect` already cover it.

## Current state (grounding)

- **Ability system is ready.** `AbilityDefinition` (Resources/Abilities) = id/name/targeting/range/castTime/
  manaCost/animTrigger/tags/cooldownLinks/`List<AbilityEffect>`. `AbilityTargetType { Self, SingleTarget }`.
  `DamageEffect` (baseDamage + `ScalingStatType` × factor → `Health.TakeDamage`) and `HealEffect`
  (baseHeal + scaling → `Health.Heal`) already exist; `ScalingStatType` has Str…Cha. `PlayerAbilities.TryCast`
  validates known/cooldown/range (skipped for Self)/mana, **consumes mana** (`_mana.UseMana`), applies each
  effect, fires `animTrigger` via ClientRpc (empty = none), starts the cooldown, and chat-notifies.
  `SetRaceClass` populates `_knownAbilities` + fills the hotbar (slots = keys 2–9) from
  `cls.startingAbilities`. So a new ability = a new asset + effect; **no engine code to touch.**
- **Existing abilities:** `Kick.asset` (animTrigger "Kick", **effects empty** — anim + 10s cooldown only) and
  `Taunt.asset`. Warrior's `startingAbilities` already = Kick (+Taunt).
- **Classes:** Warrior = real (Phase 2). Wizard/Cleric = 3.1.4 **placeholders** — Wizard INT-caster
  (baseInt 14, caster HP/mana formula), Cleric WIS-healer (baseWis 14, healer formula); both currently have
  **no** `startingAbilities`. Values already match the locked HP/mana model in CLAUDE.md.
- **Body model:** `PlayerModel` (3.1.4) instantiates the Synty body at runtime + wires the Animator. All
  bodies are Humanoid, so a hand bone is reachable rig-independently via
  `Animator.GetBoneTransform(HumanBodyBones.RightHand)` — the clean attach point for a weapon prop.
- **Weapon prefab inventory (adopted packs):** Warrior → `SM_Wep_Sword_01` / `SM_Wep_Axe_01`
  (PolygonAdventure); Wizard → `SM_Prop_WizardStaff_01` (Fantasy Characters) or `SM_Wep_Staff_01`; Cleric →
  **no mace exists** anywhere (candidates: `SM_Prop_Sceptre_01`, a spellbook). Dwarf has `SM_Wep_Dwarf_01`.

## Decisions

### CS1 — Class stats/formulas — **recommend: confirm the formulas (already correct), tune base-stat spread**
The 3.1.4 placeholder HP/mana fields already match the locked model, so this is mostly setting a per-class
**base-stat spread** so archetypes differ (Warrior high STR/STA, Wizard high INT, Cleric high WIS) — a quick
pass in the Race & Class Editor. Confirm Warrior's Phase-2 stats are still right.

### CS2 — Signature abilities — **recommend: Wizard nuke + Cleric heal (new), Warrior Kick gets a DamageEffect**
- **Wizard** — e.g. "Fire Bolt": `SingleTarget`, range ~20, manaCost ~10, `DamageEffect` baseDamage ~12 +
  `Int` scaling ~0.5, GCD (empty cooldownLinks).
- **Cleric** — e.g. "Minor Heal": `Self` (CS4), manaCost ~10, `HealEffect` baseHeal ~20 + `Wis` scaling ~0.5, GCD.
- **Warrior** — give the existing **Kick** a `DamageEffect` (baseDamage + `Str` scaling), manaCost 0 (warrior
  abilities are free). Keeps its Kick animation; now actually hits. (Taunt stays as-is.)

### CS3 — startingAbilities — **recommend: one signature on each class's hotbar**
Warrior keeps Kick (+Taunt); Wizard gets the nuke; Cleric gets the heal. `SetRaceClass` auto-places them on
the hotbar (key 2), so no UI work.

### CS4 — Heal targeting — **recommend: Self only for MVP**
`AbilityTargetType.Self` heals the caster (`ResolveTarget` → `netIdentity`), no friendly/target-of-target
plumbing. Friendly + group heals arrive with grouping/M4. Testable solo (take mob damage → self-heal).

### CS5 — Cast animation — **RESOLVED: wire a real Mixamo "Cast" clip via the existing `AddTriggeredState` pattern**
User fetches a Mixamo cast/spell clip → drops it in `Assets/Animations/Locomotion` (Humanoid, Loop off). Extend
`PlayerAnimatorSetup` to match it (filename keyword "cast") and build a **"Cast"** trigger state (same as the
Attack/Kick states). The Wizard nuke + Cleric heal set `animTrigger = "Cast"` — one shared cast gesture for both
casters (MVP; per-spell anims later). Warrior's Kick keeps its "Kick" trigger.

### CS6 / CS7 — Weapon props — **DEFERRED to 3.1.6**
Not in 3.1.5. When done (3.1.6), the plan is: attach via `Animator.GetBoneTransform(HumanBodyBones.RightHand)`
(rig-independent across all three packs) in `PlayerModel`; prop + grip offset authored on `ClassDefinition`
(class name is already synced, so the client resolves it); **Warrior = `SM_Wep_Sword_01`, Wizard =
`SM_Prop_WizardStaff_01`, Cleric = `SM_Prop_Sceptre_01`** (Sceptre stands in — no mace in any pack). First step
there: verify the Synty bodies don't already ship a held weapon (some premades do) so props don't double up.
Grip offsets get tuned live in 3.1.6's preview.

### CS8 — Authoring — **recommend: extend the roster/class builder to stamp the abilities + assignments**
Mirror the 3.1.4 approach: a `Tools/Character/Build Class Content` (or extend `CharacterRosterSetup`) that
creates the two ability assets (+ their `DamageEffect`/`HealEffect` sub-assets), adds the DamageEffect to Kick,
assigns `startingAbilities` per class, and applies the base-stat spread — one click, re-runnable, so it's
immediately testable. *(Alt: author by hand in the Ability Editor + Race & Class Editor.)*
