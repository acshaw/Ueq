# 5.1.3 — Combat Pipeline: Damage Application

**Status:** ✅ Done — verified in-editor 2026-07-15.

**Third of four sibling devplans** (see `5.1.1-hit-roll.md` for full numbering/build-order/scope notes: this
project builds 5.1.1 → **5.1.3 (this one)** → 5.1.2 → 5.1.4, per the design doc's own recommended order —
Damage comes before Avoidance so Steps 1 and 3 can be tested end-to-end first). Depends on 5.1.1 existing
(consumes its resolved hit tier). Grounded in `docs/eventide_combat_pipeline.md` §4 ("Step 3 — Damage
Application, PARTIALLY DEFINED").

## Grounding
Design doc §4.1 gives approximate tier→damage percentages with Solid Hit locked as the 100%-base reference
point; Glancing/Hit/Good/Critical/Crippling are all marked "approximate, TBD." §4.2's base-damage-formula
question ("how do Strength/Dexterity scale weapon base damage") is explicitly unanswered by the doc. Current
code (`PlayerAutoAttack.ComputeDamage()`, being replaced by 5.1.1) has an informally-tuned stat-scaling term
already in production: `baseDmg × (1 + relevantStat/400)`.

## Decisions

### DM1 — Tier damage percentages — **RECOMMEND, ships as explicit placeholders**
Miss 0% (locked), Glancing ~25%, Hit ~60%, Solid 100% (locked reference), Good 110%, Critical 125%, Crippling
150% — the last three are placeholders in the same spirit as the design doc's own "approximate, TBD" framing.
A small `CombatTierDamageConfig` (a few `[SerializeField]` floats, or a tiny ScriptableObject) holds these so
they're editable without a recompile — the doc explicitly recommends treating these as tuning parameters from
day one, not hardcoded literals.

**Variance** (doc: "damage output has meaningful spread even on identical inputs... intentional, serves the
opacity design"): apply a small random variance band per tier (e.g. ±10-15%, matching the rough scale of the
OLD formula's existing variance) — exact range is a tuning parameter, not locked by the doc.

### DM2 — Base damage → stat scaling formula — **RECOMMEND, placeholder pending real design**
Doc §4.2 explicitly says this formula "is not yet defined." Recommend keeping the CURRENT scaling term —
`baseDmg × (1 + relevantStat/400)` (relevant stat = Strength for Might weapons, Dexterity for Finesse) — as
an explicit placeholder rather than inventing an untested new formula blind. It's already been informally
playtested in the current build. Revisit once §4.2's real formula gets designed (a real open question in the
source doc, not something to resolve here).
