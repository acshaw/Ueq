# Devplan 1.6.1 — Camp & session polish

**Roadmap item:** M1 → 1.6.1 (polish discovered during 1.6 testing; follows 1.6)
**Status:** ✅ Done 2026-06-22 — verified in editor: `/camp` + `/help`, camp countdown + combat gate,
pulsing HP-frame combat border, chat-clear-on-switch, and MOTD all work. (The separate, pre-existing
hotbar-label wiring quirk that resurfaced during testing was fixed independently via runtime
self-wiring in `HotbarUI`/`HotbarSlotUI` — see the 1.7 devplan note.)

> **Implementation notes:**
> - `CombatState` (`NetworkBehaviour`, synced `InCombat`, 10 s window) stamped from a single hook in
>   `Health.TakeDamage` — covers both victim and attacker since all damage routes through there.
> - `CampController` (on the NetworkManager GO) owns the 10 s cancelable countdown; both the HUD button
>   and `/camp` route through it. Cancels on movement (position drift) or entering combat; server
>   (`CharacterSelectController.OnCamp`) re-checks `InCombat` authoritatively before despawning.
> - `/help` reads a single command table in `ChatUI` (stays in sync). Chat clears on
>   `LocalPlayer.Despawned` (camp/switch) so the next character starts fresh; MOTD is sent server-side
>   from `CharacterPersistence` after the name is set (lands on the cleared log — no race).
> - Combat indicator: a red rim behind the player HP frame (`CreateHUDFrames`), pulsed by `PlayerFrame`
>   via `CombatState.OnCombatChanged`.
**Depends on:** 1.6 ✅ (camp + multi-character). **Soft tie to 1.7:** chat-clear + MOTD are cheaper on
1.7's `LocalPlayer`/ChatUI rework, so sequence the chat bits around 1.7 (see Sequencing).
**Unblocks:** nothing hard; quality-of-life before the M1 regression.

## Goal

Polish the camp/session loop surfaced in 1.6 testing: make camping a real, deliberate action
(countdown + can't camp mid-fight), give chat commands for it (`/camp`) plus a `/help` listing, and
stop one character's chat log + a missing welcome from making the session feel unfinished
(chat-clear-on-switch + MOTD).

### Scope guardrails
- **In scope:** `/camp` and `/help` chat commands; a camp **countdown** (cancelable) with a
  **not-in-combat** requirement; a lightweight **combat-state** concept (none exists yet); clearing the
  chat log when switching characters; a welcome/MOTD line on entering the world.
- **Out of scope:**
  - **Full combat-system depth** — the combat-state here is minimal (a "recently in combat" flag),
    just enough to gate camp. Threat/aggro depth stays in M3/M4.
  - **Sitting/rest mechanics, /afk, richer commands** (`/group`, `/yell`) — backlog.
  - **DB-authored MOTD** — a hardcoded constant now; moving it to config/DB fits the M2 content
    direction later.
  - **uGUI chat restyle** — that's 1.7.

---

## Approach

### 1. `/camp` and `/help` chat commands

ChatUI already routes local commands through `TryHandleLocalCommand` (it does `/font-size`). Add two:
- **`/camp`** → begins the camp countdown (below). It's a "local command" that, when the countdown
  completes, sends the existing `CampMessage` to the server. (Camp button on the HUD shares the same
  countdown path.)
- **`/help`** → prints the command list locally (System-styled lines). Drive it from a **single
  ordered command table** `(command, usage, description)` in ChatUI so `/help` stays in sync as the
  source of truth. Current set to list: `/say <msg>`, `/shout <msg>`, `/whisper <name> <msg>`,
  `/camp`, `/help`, `/font-size <1-5>`.

### 2. Camp countdown + not-in-combat gate (D1, D2)

Camp becomes deliberate rather than instant:
- On camp request (button or `/camp`): if **in combat** → refuse with a System message ("You can't
  camp while in combat."). Else start a **countdown** (D1) shown in chat/HUD ("Camping… 10").
- The countdown **cancels** if the player **moves** or **enters combat** (take/deal damage), with a
  "Camp cancelled." message.
- On completion, send `CampMessage` (server saves + despawns → back to character select, as in 1.6).
- Countdown is **client-side** for the timer/feedback, but the **server re-checks** combat-state when
  it receives `CampMessage` (authoritative — never trust the client that it's safe to camp).

### 3. Lightweight combat-state + indicator (D2, D3)

No "in combat" notion exists today, so add a minimal one — and surface it on the HP frame:
- A small **`CombatState`** `NetworkBehaviour` on the player: server tracks `LastCombatTime` and drives
  a **`[SyncVar] bool InCombat`** (`now - LastCombatTime < CombatWindow`, D2 = 10 s) so **clients can
  react** (the indicator). A `SyncVar` hook fires an `OnCombatChanged` event for the UI.
- Stamped on **taking** damage (hook `Health.OnDamaged`) and on **dealing** damage (auto-attack +
  ability effects, or stamp the attacker in `Health.TakeDamage`).
- **Visual indicator (D2 addition):** a red border image on the player HP frame that **pulses/flashes
  while `InCombat`** and hides otherwise. `PlayerFrame` (now in `UI.unity`) grabs the local player's
  `CombatState` on `LocalPlayer.Spawned`, toggles/animates the border on `OnCombatChanged`. The border
  element is added in `CreateHUDFrames`.
- Reused by the server's camp re-check; also a foundation other systems can read later (rest/regen,
  "can't zone in combat", etc.).

### 4. Chat-clear on character switch + MOTD

- **Clear chat** when entering the world as a (different) character so the previous character's log
  doesn't bleed in. Pre-1.7: detect the local player going from null→set in ChatUI and clear +
  show MOTD; **post-1.7** this is a one-liner on `LocalPlayer.Spawned`. (Sequencing note below.)
- **MOTD/welcome:** the server sends a System chat line to the player on spawn (e.g. "Welcome to Ueq,
  <name>!" + a tip). Hardcoded constant for now (D4).

## Schema / API changes
None (no DB / migration). New client commands + a server `CombatState` component + a server→client
welcome message (reuses the existing chat channel).

## Files touched (indicative)
**New:** `Assets/Scripts/Combat/CombatState.cs` (NetworkBehaviour, synced `InCombat`).
**Modified:** `ChatUI.cs` (`/camp`, `/help`, command table, camp countdown + cancel, clear-on-switch),
`GameNetworkHUD.cs` (camp button routes through the countdown), `Health.cs` / `PlayerAutoAttack` /
ability effects (stamp combat-state), `CharacterSelectController.OnCamp` or `NetworkedPlayer` (server
re-check `InCombat` before despawn; send MOTD on spawn), `PlayerFrame.cs` (combat-border indicator via
`LocalPlayer` + `CombatState.OnCombatChanged`), `SceneSetup` (`CreateHUDFrames` adds the border image;
add `CombatState` to the player prefab list).

## Test plan
1. `/help` lists every command; each listed command actually works.
2. `/camp` and the HUD camp button both start the countdown and complete to character select.
3. **Combat gate + indicator:** take/deal damage → HP-frame border pulses red and `/camp` is refused;
   after the combat window clears → border off and `/camp` works.
4. **Cancel:** start camping, then move (or get hit) → "Camp cancelled," no despawn.
5. **Server authority:** a camp completing exactly as combat starts is re-checked server-side (no camp
   if `InCombat` on arrival).
6. **Chat clear:** play A (chat some), camp, enter B → B starts with a clean log + MOTD.
7. **MOTD:** entering the world shows the welcome line addressed to the character.

## Resolved decisions (approved 2026-06-21)
- **D1 — Camp countdown → 10 seconds**, cancelable by movement or entering combat.
- **D2 — "In combat" window → took or dealt damage within the last 10 s**, **plus a visual indicator**:
  a red border on the player HP frame that pulses while in combat (better than a silent gate).
- **D3 — Combat-state home → a dedicated `CombatState` `NetworkBehaviour`** (synced `InCombat` flag so
  the client indicator can react), stamped from damage events. Reusable.
- **D4 — MOTD source → hardcoded constant** now (DB/config later, per the M2 content direction).

## Sequencing
The camp countdown + combat-gate + `/camp`/`/help` are UI-independent and can land anytime. The
**chat-clear + MOTD** are noticeably cheaper on **1.7's `LocalPlayer` service** (clear/show on the
`Spawned` event) and 1.7 reworks ChatUI anyway — so doing those *after* 1.7 avoids touching ChatUI
twice. Recommended order: **1.7 → 1.6.1** (or split: camp/combat bits anytime, chat bits after 1.7).

## Done when

Camping is a deliberate, combat-gated action with a cancelable countdown (button + `/camp`), `/help`
lists the live command set, switching characters starts with a clean chat log + a welcome line, and a
minimal reusable combat-state exists — closing the polish gaps found in 1.6 testing.
