## Why

3.1.1 shipped `TitlePanel` as a functional **stub**: a flat dark background, `"UEQ"` in plain text,
and a vertical stack of buttons (Play, Quit, then a `— dev —` cluster with Host / Server Only). It works
but reads as placeholder. 3.1.2 makes the entry screen look **intentional** — the first thing a new player
sees — while keeping the **art-swap contract** intact so real art (3.1.2-later or whenever) is a pure drop-in.

**Decision this session:** ship it **art-free for now**. So the plan delivers a polished *procedural* look
(generated gradient + vignette + styled type) that stands on its own, and leaves the `Resources/UI/Title/…`
sprite hooks so `TitleBackground`/`TitleLogo` PNGs override the procedural treatment with zero code change.

## Scope boundary

- **In:** the **Title screen only** — background treatment, logo/wordmark, tagline, primary buttons, dev-control
  relocation, version label, optional entrance polish.
- **Out:** Login/Register styling (**3.1.3**), character select (**3.1.6**), any server/auth/flow change. Shared
  `MenuUI` additions here should be **additive** so 3.1.3 reuses them, not rework them.

## Decisions

### T1 — Background treatment (art-free) — **recommend: procedural vertical gradient + vignette**
A flat color reads cheap. Generate a background at runtime that looks deliberate:
- A **vertical gradient** (dark desaturated blue at top → near-black at bottom) built as a small `Texture2D`
  (e.g. 2×256) drawn full-screen. Cheap, no assets.
- A subtle **vignette** overlay (radial dark edges) for framing — a generated radial-alpha `Texture2D` or a
  simple dark border gradient.
- **Art override preserved:** if `Resources/UI/Title/TitleBackground` exists, use it (cover-fit, see T-note)
  instead of the procedural gradient.

*Alt:* single flat color (what we have) — rejected as too plain. *Alt:* animated/shader gradient — deferred
(scope/risk). Recommend static procedural.

### T2 — Wordmark / logo (art-free) — **recommend: styled TMP wordmark stand-in**
Replace the plain `Text("UEQ", 64)` with a **styled wordmark**: larger, bold, letter-spacing/tracking, an
accent color (and optionally a TMP face/underlay for a soft glow if it's low-risk with the default TMP asset).
Keep the `TitleLogo` sprite hook so a real logo image overrides the text wordmark. Tagline "A multiplayer RPG"
restyled (muted, spaced) beneath it.

### T3 — Layout — **recommend: cardless, atmospheric center stack**
Title screens usually don't sit in a boxed card. Drop the opaque `MenuUI.Card` panel for the title and center
the **wordmark → tagline → primary buttons** over the gradient (the gradient's dark lower half keeps buttons
legible). If legibility needs help, a **faint translucent strip** behind the buttons rather than a full card.

*Alt:* keep the card — rejected (looks like a dialog, not a title). This means the title diverges from the
Login/Register card look on purpose (that's fine — they're different screen types).

### T4 — Dev controls (Host / Server Only) — **recommend: relocate to a small, dim bottom-corner cluster**
Right now Host/Server Only sit in the main button stack and dominate. Move them to a compact, de-emphasized
**bottom-left "dev" cluster** (small text + small buttons) so the title reads clean for a "real" player, but
they stay one click away for you. Keep behavior identical (`HostAsDev` / `StartServerOnly`).

*Alt:* hide behind a key/toggle — more work, deferred. *Alt:* leave in place — rejected (clutters the title).

### T5 — Button styling — **recommend: explicit hover/press feedback + consistent accent**
Give `MenuUI.Button` proper `Selectable` color states (normal/highlighted/pressed/disabled) so buttons respond
to hover/keyboard focus, and a consistent accent. Do this as an **additive** `MenuUI` change (e.g. a styling
pass or an optional param) so 3.1.3's Login/Register inherit the same feel. Primary ("Play") can read as the
accent action; secondary ("Quit") muted.

### T6 — Version / build label — **recommend: small corner text**
Small dim label (e.g. bottom-right) showing `Application.version` (+ "dev" tag). Cheap, and useful once builds
ship.

### T7 — Entrance polish — **recommend: minimal (rely on the shell fade), optional gentle wordmark fade-in**
The shell already fades screens in (`ScreenFader`). For 3.1.2 keep it to that; **optionally** a short
wordmark/logo alpha fade-in on `OnShow` for a bit of life. No parallax/particles (scope). Skippable if it adds risk.

## Reusable helpers (implementation note, not a new decision)

Where it's clean, land the background treatment as a `MenuUI` helper (e.g. `MenuUI.GradientBackdrop(...)` +
`MenuUI.Vignette(...)`) and the button-state styling in `MenuUI.Button`, so **3.1.3** styles Login/Register by
reuse rather than copy. Procedural textures generated once and cached.
