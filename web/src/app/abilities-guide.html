1. The big picture

An ability is a header (identity/targeting/resource/animation) plus three ordered lists: tags (semantic labels), cooldown links (which shared timer this ability starts on cast), and effects (what actually happens, applied in order). The whole system is data-driven — a new ability is a row in the web editor, not new code. A genuinely new kind of effect (a DoT, a stun, a buff) is the one thing that still needs a code change (§8).

Everything here is entirely web-authored. Once an ability exists, assign it to a class's Starting Abilities list in the Class Editor (see the Races & Classes guide) to put it on a character's hotbar at creation. Restart the Unity host after any web edit before testing — content loads once at host start.

3. Tags vs. cooldown links — the part that trips people up

A tag (from the Ability Tag Editor) is just an id + display name — on its own it does nothing. It's used two different ways on an ability, and they're easy to conflate:

  • An ability's own Tags list is pure flavor/classification (e.g. "this is a martial ability") — nothing reads it at runtime today. It exists for future systems (combo chains, elemental typing) referenced in the original design, not yet built.
  • A cooldown link pairs a tag with a duration and means: casting this ability starts (or checks) a shared timer keyed by that tag. The tag here is a timer key, not flavor — if two different abilities both have a cooldown link on the same tag, casting either one starts one shared timer that blocks both until it expires. This is how you'd build "these three abilities share one cooldown" (a stance-dance kit, a shared "special attack" pool, …).
You can reuse the exact same tag for both purposes on one ability — e.g. Kick tags itself with MartialAbility and has a cooldown link on MartialAbility (10s) — but they're independent lists; adding a tag doesn't add a cooldown link, and vice versa.

Empty cooldown links = uses the shared Global Cooldown (GCD, 1.5s) instead of a dedicated timer. This is the default for most simple abilities (Fire Bolt, Minor Heal both have zero cooldown links today). Add a cooldown link only when an ability needs its own longer, independent timer.

4. Effects, in depth

Effects apply in order when the ability successfully casts (after the range/mana/ cooldown checks all pass). Each effect row is one of two types today:

TypeFormulaNotes
damagebaseAmount + scalingStat × scalingFactor, minimum 1, applied via Health.TakeDamageIgnores the target's mitigation/avoidance pipeline entirely — an ability's damage always lands if the ability resolves (no Dodge/Parry/Miss roll like auto-attack). This is a real, intentional gap from the design doc's original scope (see the Combat Pipeline guide) — abilities/spells were explicitly left on the old formula, not migrated to the 4-step resolver.
healbaseAmount + scalingStat × scalingFactor, minimum 1, applied via Health.HealNo overheal cap beyond max HP (Health clamps internally).

Scaling stat is one of None/Str/Sta/Agi/Dex/Int/Wis/Cha, read off the caster's CharacterStats at cast time (not the target's). None means the effect is a flat number regardless of stats.

Multiple effects on one ability all apply, in list order, to the same resolved target (Self or the selected target) — there's no per-effect target override. A "damage + apply a debuff" ability would need a Debuff effect type, which doesn't exist yet (§8).

5. The Ability Tag Editor

A separate, much simpler editor — just tag_id + display name, no children. Create a tag here first, then reference it from an ability's Tags or Cooldown Links section (both pull their dropdown options from this list). Deleting a tag that's still referenced by an ability's cooldown link or tag list will fail at the database level (a foreign-key error) — remove the reference from the ability first.

6. Getting an ability onto a character

Creating an ability doesn't put it anywhere by itself. Two ways it reaches a player:

  1. Starting abilities — add the ability's id to a class's Starting Abilities list in the Class Editor (see the Races & Classes guide). New characters of that class get it auto-filled onto the hotbar at creation.
  2. There is currently no in-game way to grant an ability after creation (no "learn ability" flow, no trainer NPC, no levelup unlocks) — that's future scope, not built.

7. Recipes (step-by-step)

Web app in this browser UI Unity in the Unity editor

Recipe A — A simple instant-damage attack

Goal: a Fire-Bolt-style single-target nuke, no dedicated cooldown (just the GCD).

  1. Web app Ability Editor → + New. Set ability_id (e.g. ice_shard), display name, targeting = Single Target, a range, a mana cost, and an anim trigger that already exists in the controller (e.g. Cast).
  2. Web app Leave Tags and Cooldown Links empty (uses the GCD).
  3. Web app Effects → + Effect → type damage, set a base amount and a scaling stat/factor. Save.
  4. Web app Class Editor → open the target class → Starting Abilities → add the new ability id (or wire it in later via whatever future ability-grant path exists).
  5. Unity Restart the host, create/relog a character of that class, confirm it's on the hotbar and casts correctly.

Recipe B — A self-heal

Goal: Minor-Heal-style self-target restoration.

  1. Web app Ability Editor → + New. Targeting = Self (range is ignored). Set mana cost and an anim trigger.
  2. Web app Effects → + Effect → type heal, set base amount + scaling stat (typically Wis).
  3. Web app Wire into a class's Starting Abilities as in Recipe A.

Recipe C — Two abilities sharing one cooldown

Goal: a "stance" pair where using either one locks out both for 15s.

  1. Web app Ability Tag Editor → + New → create a tag, e.g. stance.
  2. Web app On both abilities: Cooldown Links → + Link → select stance, duration 15.
  3. Unity Restart the host and confirm: casting either one starts a single 15s timer that also blocks the other (check the hotbar cooldown overlay on both slots).

8. Known gaps — what's still placeholder or unimplemented

  • Only two effect types exist: damage and heal. The original design named several more (Dot, Hot, Buff, Debuff, Snare, Root, Stun, FactionHit) — none are built. Adding one is a real code change (a new effect_type value, a new branch in AbilityRegistry. BuildEffect, and if it needs fields beyond the shared amount/scaling-stat/scaling-factor shape, a schema migration) — not something the web editor alone can add.
  • Ability damage/healing bypasses the 4-step combat resolver entirely. No Dodge/ Parry/Riposte/Miss roll, no mitigation — an ability that successfully casts always lands its full effect. This is a known, intentional-for-now scope gap (see the Combat Pipeline guide).
  • Cast time is stored but not enforced. A nonzero cast time doesn't currently block movement or add a visible cast bar beyond the trigger animation.
  • No post-creation ability-grant flow. Starting Abilities at character creation is the only way an ability reaches a player today.

9. Troubleshooting

SymptomLikely cause / fix
An ability's animation never playsThe Anim Trigger text doesn't exactly match a Trigger parameter in PlayerLocomotion.controller — this fails silently, no error logged.
Casting one ability also puts an unrelated ability on cooldownThey share a cooldown-link tag (§3) — check both abilities' Cooldown Links sections.
An ability I just created isn't on any character's hotbarIt needs to be added to a class's Starting Abilities in the Class Editor, and that only applies to newly created characters (§6) — nothing retroactively grants it to existing ones.
Deleting a tag failsIt's still referenced by an ability's Tags or Cooldown Links list — remove the reference there first (§5).
My web edit to an ability didn't change in-game behaviorUnity loads ability content at host start — restart the Unity host. Also confirm Postgres + the API are running.
