To-Hit & Damage — Formula Reference

The complete, variable-by-variable formula chain for a single swing — Hit Roll → Avoidance → Damage → Mitigation — written out symbol by symbol, with every symbol defined in the Glossary below. This page is a reference, not a how-to — for authoring recipes ("how do I make a boss mob"), see the Combat Pipeline guide; for interactively watching these formulas run against real numbers, use the Combat Simulator's "Swing trace" panel.

1. How to read this page

Every variable below is tagged one of two ways:

  • Raw — a value that's simply stored somewhere (a character stat, an authored field on a class/mob/item). It isn't computed from anything else in this pipeline. If it's a plain character stat like STR, that's all it is — a number sitting on the character.
  • Derived — computed from other variables via a formula given right next to it in the Glossary. Follow the formula's own inputs to see what they are (Raw or also Derived) — the chain always bottoms out at Raw values.
Players vs. mobs: players compute ATK and Defense from real character stats + trained weapon skill (Steps below). Mobs have no CharacterStats — they skip that derivation entirely and author ATK / avoidance stand-ins as flat Raw numbers instead. Both feed the exact same downstream pipeline from that point on.

2. Pipeline at a glance

StepAnswersReadsProduces
1. Hit RollWhich of the 7 tiers (Miss…Crippling) did this swing land at, before either side's avoidance is checked?Attacker's ATK, both combatants' Level, whether this is a rear attackRawTier
2. AvoidanceDid the defender turn that tier into a Miss (and possibly counter-attack)?Defender's three independent Dodge/Parry/Riposte values (or mob stand-ins), whether the attack is parryableFinalTier, Riposted
3. DamageHow much HP does that tier actually take off? Weapon base damage, attacker's relevant stat, FinalTier Damage (and RiposteDamage if riposted)
4. MitigationDoes the defender's armor reduce that number? DamageFinalDamage
Step 4 is a no-op today. FinalDamage = Damage, unchanged — there is no armor/mitigation formula implemented yet (design doc §5, still open). It's kept as a named seam in the code so nothing else needs to change when it's built.

3. Step 1 — Hit Roll (the formula)

// ATK — where this combatant's base table sits (players: derived from skill+stat+trained Offense; mobs: authored)
EffectiveSkill   = WeaponSkill + RelevantStatForAtk × StatToSkillRatio      // players only, §2.10
ATK              = EffectiveSkill + Offense                                // players — Offense is trained, see §7.2/§7.6
ATK              = MobAtk                                                  // mobs — authored directly, no formula

// Base table — ATK picks a point along ONE shared curve
AtkFraction      = clamp01( (ATK − MinAtk) / (MaxAtk − MinAtk) )
BaseTable        = lerp( Level1Table, Level20Table, AtkFraction )          // 7 weights, sum = 100

// Level Differential — reshapes BaseTable using the actual opponent's level
LevelGap         = AttackerLevel − DefenderLevel
LowLevel         = min( AttackerLevel, DefenderLevel )
Increments       = IncrementsToFutility( LowLevel )                        // Fibonacci band lookup
LevelFraction    = clamp01( |LevelGap| / Increments )

Table = BaseTable
if LevelGap < 0:  Table = ShiftTowardFutility( Table, LevelFraction × MaxLevelFutilityWeight )
if LevelGap > 0:  Table = ShiftTowardPotency ( Table, LevelFraction × MaxLevelFutilityWeight × LevelAdvantageScale )
// LevelGap == 0 → Table unchanged

// Position Modifier — only if the attacker is behind the defender's facing
if IsRearAttack:  Table = ApplyPositionModifier( Table, RearAttackWeight )

// The actual dice roll
RawTier          = WeightedPick( Table )    // random draw, weighted by the 7 final tier values

ShiftTowardFutility / ShiftTowardPotency: move amount weight units out of a fixed set of "drain" tiers — proportional to how much weight each drain tier currently holds — into a fixed set of "fill" tiers, split evenly. Futility drains Crippling→Critical→Good→Solid→Hit and fills Miss/Glancing (a level disadvantage makes the worst outcomes more likely). Potency drains Miss/Glancing/Hit and fills Solid/Good/Critical (a level advantage makes the best outcomes more likely, but only at half strength — LevelAdvantageScale). Crippling never gains weight from this — it only ever loses it.

ApplyPositionModifier: pulls up to RearAttackWeight weight units — proportionally from whatever Miss/Glancing/Hit currently hold — and moves all of it into Solid Hit only. A rear attack makes a clean, reliable hit more likely; it does not push toward Good/Critical/Crippling.

4. Step 2 — Avoidance (the formula)

// Checked in this order — first success wins, and it's binary (nothing partial)
RiposteChance = AvoidanceChance( Defender.Riposte )
Riposted      = roll(0,100) < RiposteChance

if not Riposted and IsParryable:
    ParryChance = AvoidanceChance( Defender.Parry )     // independently trained — no longer shares Riposte's value
    Parried     = roll(0,100) < ParryChance

if not Riposted and not Parried:
    DodgeChance = AvoidanceChance( Defender.Dodge )
    Dodged      = roll(0,100) < DodgeChance

FinalTier = Miss     if Riposted or Parried or Dodged
          = RawTier  otherwise

Defender.Dodge/Parry/Riposte here are three independent, fully-resolved values (players: derived from Agility + trained Defense/Dodge/Parry/Riposte skills; mobs: authored directly, AV3) — see the Glossary's Avoidance sections. AvoidanceChance(stat) is a fixed piecewise-linear curve, not a simple formula — see §8.

If IsParryable is false (a beast bite/claw, unarmed strike), the Parry check is skipped entirely and falls straight through to Dodge — Riposte is unaffected either way.

5. Step 3 — Damage (the formula)

if FinalTier == Miss:
    Damage = 0
else:
    TierPercent        = TierDamagePercent[ FinalTier ]                    // fixed lookup table
    VarianceMultiplier = 1 + rand(−1, +1) × DamageVariance
    BaseDamageWithStat = ( RelevantStat × StatToDamagePercentRatio × WeaponBonusDamage ) + WeaponBaseDamage
    RawDamage          = BaseDamageWithStat × TierPercent × VarianceMultiplier × ExtraMultiplier
    Damage             = max( 1, round(RawDamage) )                        // floor of 1 on any non-Miss hit

// Riposte counter-attack — computed only if Riposted (Step 2), bypasses Step 2 and Step 4 entirely
if Riposted:
    RiposteDamage = (the Damage formula above, with FinalTier forced to Solid Hit
                     and ExtraMultiplier = RiposteDamageMultiplier)
RelevantStat here is the raw stat, not EffectiveSkill/ATK. It's the attacker's raw STR (Might weapon) or DEX (Finesse weapon) — the same stat that feeds ATK's EffectiveSkill term upstream, but plugged into a completely separate formula here. ATK itself does not appear anywhere in the Damage step. 2026-08-21 rework: a weapon's damage now splits into two authored numbers — WeaponBaseDamage (flat, unaffected by stats) and WeaponBonusDamage (the stat-scalable portion). RelevantStat converts to a percentage via × StatToDamagePercentRatio (0.01 — so STR/DEX 100 = 100%) with no cap; that percentage of WeaponBonusDamage is added to WeaponBaseDamage. Itemization determines the practical ceiling by choosing how much of a weapon's damage lives in each field. For mob attackers, RelevantStat is always 0 — mobs have no CharacterStats, so a mob's Attack damage field (mapped to WeaponBaseDamage) is treated as already representing its full power; the WeaponBonusDamage term is always a no-op for mobs regardless of its value.

6. Step 4 — Mitigation

FinalDamage = ApplyMitigation( Damage, Defender ) = Damage   // stub — always a no-op today

Named seam only. There is currently no way for armor, buffs, or any defender property to reduce a landed hit's damage after Step 3 computes it. See the Combat Pipeline guide §8 for what this means in practice for mob authoring.
