Combat Pipeline — Mob Author Guide

How to fill in a mob's Combat Pipeline (5.1) section in the Mob Editor — the fields that drive its hit rolls, avoidance, and damage. Mobs run the exact same four-step resolver as players; nothing here is derived from Level automatically, so every mob's numbers are whatever you type.

1. The big picture

Every swing — player-vs-mob or mob-vs-player — resolves through the same static CombatResolver.ResolveAttack(...) call, in four steps: Hit Roll → Avoidance → Damage → Mitigation. A player's Hit Roll table comes from interpolating their class's Level 1→20 table; a mob's Hit Roll table is authored directly on the mob — a flat set of numbers you type in, not derived from its Level. That's the entire point of the Combat Pipeline section: it's the mob-side equivalent of a player's class + stats + weapon skill, all in one place.

Mental model: the 7 tier weights you enter are this mob's hit-tier distribution at parity — as if it were fighting an opponent of the same level with comparable skill. Level and skill differences from the actual opponent shift that table automatically at runtime (§6) — you don't author those shifts, only the starting point.

2. The four steps, in plain language

StepWhat happensStatus
1. Hit RollRoll against a weighted table of 7 outcomes (Miss → Crippling), after Level/Skill/Position modifiers reshape it.Fully implemented
2. AvoidanceRiposte → Parry → Dodge, checked in that order against the defender's stats. Any success turns the whole swing into a Miss (Riposte also counter-attacks). Fully implemented
3. DamageThe surviving tier converts to a number: weapon base damage × a per-tier percentage × random variance.Fully implemented
4. MitigationWould apply armor/buffs to reduce the Step 3 number. No-op stub — whatever Step 3 computes is final (§8)

4. Anatomy of the Combat Pipeline section

FieldMeaning
Weapon category (Might / Finesse)Which of the opponent's two per-category weapon skills gets compared against this mob's Weapon skill for the Skill Differential roll below. It has no effect on this mob's own damage — mobs have no Strength/Dexterity to scale with (that's what Might/Finesse scale for a player); a mob's damage always comes from its flat Attack damage field. Pick whichever matches the mob's fluff (blunt/heavy → Might, claws/blades → Finesse) — it only matters in fights against players, since only players track per-category skill.
Weapon skill (number)This mob's own trained proficiency. Compared against the opponent's weapon skill for the Skill Differential modifier (perfect-square scaling, capped at ±5 net difference: ±1→1 weight unit, ±2→4, ±3→9, ±4→16, ±5 or more→25, moved toward/away from the top tiers). A player's own skill cap at level L is 5 + 5×(L−1) — nothing enforces a matching value here, but authoring roughly 5 + 5×(mobLevel−1) keeps a same-level fight even.
Attack parryable (Yes/No)Yes = a weapon-style swing a defender can Parry. No = beast/unarmed-style (bite, claw, ram) — skips the Parry check entirely and falls straight to Dodge. Has no effect on Riposte or Dodge.
Avoidance Agility / Avoidance Dexterity (numbers)Stand-ins for the Agility/Dexterity a player would use — mobs have no CharacterStats. Same numeric scale as a player stat: the dodge curve sits near-flat (~0.1%) below 50, ramps to ~5% around 100, and asymptotes near 15% past ~210 (most players gear to 60–150; Monks higher). Dexterity currently drives both Riposte and Parry — they reuse the identical curve shape (not yet differentiated), so raising it raises both by the same amount. Low defaults (20/20) sit in the curve's flat near-zero floor.
The 7 tier weights (Miss → Crippling)This mob's hit-tier distribution at parity. See §5 — read this before typing numbers, the total matters more than it looks like it should.

5. The seven tier weights, in depth

These are relative weights, not literal percentages — the roll is Random.Range(0, total) against the cumulative sum, so only the ratios between the seven numbers decide the odds. A freshly-created mob defaults to the Warrior Level 1 table (17.5 / 40 / 30 / 10 / 2.5 / 0 / 0), which happens to total 100 — that's a convention, not a requirement.

⚠️ But the total isn't free to ignore. The automatic modifiers in §6 move fixed weight units, not fixed percentages: a rear attack always pulls up to 50 units into Solid Hit; Level Differential can move up to 100; Skill Differential up to 25. Those magnitudes were tuned assuming a table totaling roughly 100 (the seeded default). If you author a mob with a much smaller total — say 1/1/1/0/0/0/0 — a single rear attack (50 units) completely swamps it and every rear hit lands as a guaranteed Solid Hit. Keep your total in the same ballpark as the default unless you deliberately want the modifiers to dominate or barely register.

Crippling is different for mobs than for players. A player's Crippling weight always stays at 0 until a passive-unlock system (which doesn't exist yet) — the design intentionally redistributes those points into Critical instead. A mob has no such restriction: type a nonzero Crippling weight and it rolls normally. Useful for an intentionally terrifying boss-tier hit.

6. What's computed automatically at runtime

These are not fields you set — they shift your authored table on every swing, on top of whatever you typed:

ModifierWhenEffect
Level DifferentialEvery swing, this mob's Level vs. the opponent's Under-level shifts weight toward Miss/Glancing at full strength; over-level shifts toward Solid/Good/ Critical at half strength (advantage helps less than disadvantage hurts). The same absolute level gap swings harder at low levels than at high levels (Fibonacci band structure, §2.7 of the design doc).
Skill DifferentialEvery swing, this mob's Weapon skill vs. the opponent's (category picked by Weapon category)See §4's Weapon skill row.
Position (rear attack)Only when the attacker is behind the defender's facing Pulls up to 50 weight units into Solid Hit only — doesn't touch Good Hit/Critical/Crippling. Reliability, not explosiveness. Works both ways: a player attacking a mob from behind gets it, and so does a mob that manages to circle behind a player.
Damage varianceEvery non-Miss hit± a shared variance band (12.5% by default) so identical tier rolls don't produce identical numbers. Not per-mob — one shared config (§8).
Avoidance waterfallEvery non-Miss hit, against the defender's stand-insRiposte (Dexterity) → Parry (Dexterity, skipped if not parryable) → Dodge (Agility) — first success wins, binary (full Miss, or nothing). Riposte additionally fires a counter-attack (§8).

7. Recipes (step-by-step)

All of this is entirely web-authored — no Unity Inspector editing needed once the mob has a body and Spawn Point (see the Spawn System guide). Restart the Unity host after any web edit before testing.

Web app in this browser UI Unity in the Unity editor

Recipe A — A straightforward brute (weapon-style, average evasion)

Goal: a level-appropriate melee mob that fights roughly like a same-level Warrior.

  1. Web app Mob Editor → open or create the mob. Set Level and Attack damage in the Combat section as usual.
  2. Web app Combat Pipeline section: Weapon category = Might (or Finesse, per fluff), Weapon skill ≈ 5 + 5×(Level−1), Attack parryable = Yes.
  3. Web app Leave Avoidance Agility/Dexterity at the default (20/20) for an average, not-especially-evasive defender.
  4. Web app Leave the 7 tier weights at the seeded default (17.5/40/30/10/2.5/0/ 0) unless you want this mob noticeably tougher or weaker than baseline. Save.
  5. Unity Restart the host. Fight it — expect the usual Miss/Glancing/Hit/ Solid/Good spread, shifted by your relative level and weapon skill.

Recipe B — An evasive, unparryable beast

Goal: a wolf/wildcat-style mob that dodges often and can't be Parried (it has no weapon).

  1. Web app Combat Pipeline section: Attack parryable = No (bites/claws skip Parry, going straight to Dodge).
  2. Web app Raise Avoidance Agility well above default — e.g. 100 lands around 5% dodge, 150+ starts approaching the higher end of the curve (§4). Dexterity can stay low if you don't want it to also Riposte/Parry-shaped-dodge often (Parry is moot here since it's unparryable, but Dexterity still drives Riposte).
  3. Web app Optionally shift the 7 tier weights toward Glancing/Hit and away from Solid/Good — a beast that's hard to pin down but doesn't hit as hard when it lands. Save.
  4. Unity Restart the host. Fight it — expect more frequent "you miss" than Recipe A, from Dodge succeeding rather than a low Hit Roll tier.

Recipe C — A dangerous high-level boss

Goal: a mob that can land a genuinely scary hit, including a Crippling tier players don't get to see from other mobs.

  1. Web app Set a high Level and Attack damage — remember Attack damage is the Step 3 input, not the final number that lands (§8); a Solid Hit (100%) is closest to it, other tiers scale it up or down.
  2. Web app Give the 7 tier weights a small explicit Crippling value (e.g. 2–3) — unlike a player, nothing blocks this. Shift some weight out of Miss/Glancing into Solid/Good/Critical to make the boss feel dangerous even before Level Differential kicks in.
  3. Web app Consider raising Avoidance Agility/Dexterity too, if you want the boss to be hard to land clean hits on as well as hard to survive.
  4. Unity Restart the host and fight it at the intended player level — the Level Differential modifier does a lot of the "this fight is dangerous" work on its own once there's a real level gap.

8. Known gaps — what's still placeholder or unimplemented

  • Mitigation (Step 4 — armor) is a complete no-op today. Whatever Step 3 computes is the final damage applied to HP, full stop. There is currently no way to give a mob "high armor" that reduces incoming damage after a hit lands — the only levers that make a mob harder to damage are the Step 1/2 levers above (a tougher tier table, higher avoidance) plus raw Max health.
  • Attack damage's meaning changed with 5.1. Before this pipeline existed it was a flat, guaranteed per-hit number. Now it's the Step 3 weapon base damage input: the number actually applied is Attack damage × tier% × variance. A Glancing hit does far less than the raw field value; a Good/Critical hit does somewhat more; only a Solid Hit (100%, the locked reference point) is close to the raw number.
  • A mob's Riposte counter-hit uses the original attacker's weapon numbers, not this mob's own Attack damage. If a player attacks this mob and it Riposte-succeeds, the counter-attack damage is calculated from the player's weapon base damage and stat (at a reduced multiplier) — so a heavily-geared player takes a proportionally harder counter-hit back, regardless of what this mob's own Attack damage is set to.
  • Parry and Riposte reuse the identical Dodge curve shape. The design doc treats their real curve values as an open tuning question — until that's differentiated, Avoidance Dexterity controls both at the same rate.
  • The Agility 1–250 dodge curve is a piecewise-linear approximation across ~11 control points (AvoidanceCurve.cs), not the design doc's full per-point table (referenced there but not included). Values between control points are linearly interpolated — close, not exact.
  • Damage variance and the per-tier damage percentages are shared, not per-mob. One CombatTierDamageConfig asset (Resources-optional; placeholder defaults if absent) applies to every mob and player alike — there's no way to give one mob "less variance" or "a bigger Critical bonus" than another from the Mob Editor today.
  • Player-side class tables are themselves still placeholder for Cleric/Wizard (a budget-ratio-scaled stand-in, seeded via Tools → Combat → Seed Class Combat Tables in Unity) — only Warrior's Level 1→20 table is the design doc's real numbers. Keep that in mind if you're tuning a mob "to feel fair against a level-20 Wizard" — the Wizard side of that comparison is a placeholder too.

9. Troubleshooting

SymptomLikely cause / fix
A rear attack against this mob (or by it) always lands as a guaranteed Solid Hit Your 7 tier weights total far less than ~100 — the 50-unit rear-attack shift dominates a small table (§5). Scale your weights up, keeping the same ratios.
This mob's hit distribution feels much harsher or softer than intended against a specific opponentCheck the Level and Weapon skill gap — both modifiers are large relative to a ~100-total table (up to 100 and 25 weight units respectively) and apply on every swing.
This mob never lands a Critical, even when clearly favoredCritical can gain weight from Level/Skill advantage even starting from 0 — check the opponent's actual level/skill first. Crippling never gains weight from any modifier — it only appears if you typed a nonzero value directly (§5, §8).
My web edit to the Combat Pipeline section didn't change in-game behaviorUnity loads mob content at host start — restart the Unity host. Also confirm Postgres + the API are running.
A mob's Riposte counter-hit seems to scale with the player, not the mobExpected — see §8. The counter uses the original attacker's weapon numbers, not this mob's Attack damage.
An "Attack parryable = No" mob still gets Riposted or Dodged againstExpected — the parryable flag only skips the Parry check; Riposte and Dodge still run normally (§6).
