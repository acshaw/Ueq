Combat Pipeline — Mob Author Guide

1. The big picture

Every swing — player-vs-mob or mob-vs-player — resolves through the same static CombatResolver.ResolveAttack(...) call, in four steps: Hit Roll → Avoidance → Damage → Mitigation. As of 5.1.5, Hit Roll's base table is derived from ATK instead of authored directly: a player's ATK comes from trained weapon skill + a relevant stat + their class's ATK formula; a mob's ATK is authored directly as one number — mobs have no stats to derive it from. Either way, ATK picks a point along ONE shared curve (the Warrior Level 1 → Warrior Level 20 reference tables) instead of each class or mob authoring its own 7-weight table. That's the entire point of the Combat Pipeline section: it's the mob-side equivalent of a player's class + stats + weapon skill, collapsed to a single tunable number.

Mental model: ATK is a single "how dangerous is this attacker's Hit Roll" score. Higher ATK moves the resulting table toward the Level 20 reference (more Solid/Good/Critical, less Miss/Glancing); lower ATK moves it toward the Level 1 reference. Level differences from the actual opponent shift that table further at runtime (§6) — you don't author those shifts, only the ATK starting point.

2. The four steps, in plain language

StepWhat happensStatus
1. Hit RollATK picks a base table along the shared Level 1 → Level 20 curve; Level and Position modifiers reshape it; roll against the weighted result (Miss → Crippling). Fully implemented
2. AvoidanceRiposte → Parry → Dodge, checked in that order against the defender's stats. Any success turns the whole swing into a Miss (Riposte also counter-attacks). Fully implemented
3. DamageThe surviving tier converts to a number: weapon base damage × a per-tier percentage × random variance.Fully implemented
4. MitigationWould apply armor/buffs to reduce the Step 3 number. No-op stub — whatever Step 3 computes is final (§8)

4. Anatomy of the Combat Pipeline section

FieldMeaning
Weapon category (Might / Finesse) — vestigial as of 5.1.5Used to feed the retired Skill Differential modifier. No longer read by the resolver — left on the mob record for now, may be removed in a future cleanup pass. Doesn't affect anything you author today.
ATK (number)This mob's Hit Roll potency, authored directly — the mob-side equivalent of a player's EffectiveSkill + ClassAtkBase(level). See §5.
Attack parryable (Yes/No)Yes = a weapon-style swing a defender can Parry. No = beast/unarmed-style (bite, claw, ram) — skips the Parry check entirely and falls straight to Dodge. Has no effect on Riposte or Dodge.
Avoidance Dodge / Parry / Riposte (numbers) Three independent stand-ins for what a player would reach via AvoidanceBase + a trained skill (2026-08-13 Avoidance rework) — mobs have no CharacterStats or trained skills, so each check reads its own authored number directly, with no shared base between them. Same numeric scale as a player's resolved value: the underlying curve sits near-flat (~0.1%) below 50, ramps to ~5% around 100, and asymptotes near 15% past ~210. Low defaults (20/20/20) sit in the curve's flat near-zero floor. Raising one has no effect on the other two — each is genuinely its own dial now.

5. ATK, in depth

ATK is a single number that decides where this mob's Hit Roll table sits between two fixed reference points: MinAtk (→ the Warrior Level 1 table, weighted toward Miss/Glancing) and MaxAtk (→ the Warrior Level 20 table, weighted toward Solid/Good/Critical). Both the band (MinAtk/MaxAtk) and the two reference tables are shared, global constants — not something you author per-mob. Set ATK at or below MinAtk for the weakest possible Hit Roll table; at or above MaxAtk for the strongest.

A newly-created mob defaults its ATK to the MinAtk floor — a sane, non-degenerate starting point, not zero. Tune ATK in the Combat Simulator before saving it here — load the mob (or a comparable one) there, watch the swing-analysis tier bars and DPS update live as you adjust ATK, then copy the number back into the Mob Editor.

For reference, a player's ATK is EffectiveSkill + Offense, where EffectiveSkill = weapon skill (assumed trained to the level's cap in the simulator; earned through use in the real game, 2.12) + relevant stat × 0.1 (design doc §2.10) and Offense is a trained stat, same treatment as weapon skill — starts at 1, earned through use, capped at level × 5 (no class involvement either way; the simulator assumes it's trained to the level's cap, same convention as weapon skill). Avoidance mirrors this exactly (2026-08-13 rework): Defense is a trained stat like Offense (starts at 1, capped at level × 5); AvoidanceBase = Agility × 0.1 + Defense feeds Dodge only (EffectiveDodge = AvoidanceBase + trained Dodge skill, capped like weapon skill — level×5+5 — so Dodge works even before it's trained, an innate/reflexive check); Parry and Riposte are each their own trained skill standing completely alone (no AvoidanceBase contribution — genuinely ~0% until trained). Mobs don't use any of this — they author ATK and all three avoidance checks (Dodge/Parry/Riposte) directly, same reasoning as Attack damage. Authoring a mob "to feel fair against a level-N player of class C" means picking an ATK (and avoidance numbers) in the same rough neighborhood as that player's own computed values at level N — the Combat Simulator's "Load class…" picker computes this for you.

6. What's computed automatically at runtime

These are not fields you set — they shift the ATK-derived table on every swing, on top of wherever ATK placed it:

ModifierWhenEffect
Level DifferentialEvery swing, this mob's Level vs. the opponent's Under-level shifts weight toward Miss/Glancing at full strength; over-level shifts toward Solid/Good/ Critical at half strength (advantage helps less than disadvantage hurts). The same absolute level gap swings harder at low levels than at high levels (Fibonacci band structure, §2.7 of the design doc).
Position (rear attack)Only when the attacker is behind the defender's facing Pulls up to 50 weight units into Solid Hit only — doesn't touch Good Hit/Critical/Crippling. Reliability, not explosiveness. Works both ways: a player attacking a mob from behind gets it, and so does a mob that manages to circle behind a player.
Damage varianceEvery non-Miss hit± a shared variance band (12.5% by default) so identical tier rolls don't produce identical numbers. Not per-mob — one shared config (§8).
Avoidance waterfallEvery non-Miss hit, against the defender's three independent valuesRiposte → Parry (skipped if not parryable) → Dodge — first success wins, binary (full Miss, or nothing). Riposte additionally fires a counter-attack (§8).
5.1.1's Skill Differential modifier (comparing attacker vs. defender weapon skill) was retired in 5.1.5 — weapon skill's influence now flows through the attacker's ATK instead of a separate runtime comparison. There's no equivalent row here anymore.

7. Recipes (step-by-step)

All of this is entirely web-authored — no Unity Inspector editing needed once the mob has a body and Spawn Point (see the Spawn System guide). Restart the Unity host after any web edit before testing.

Web app in this browser UI Unity in the Unity editor

Recipe A — A straightforward brute (weapon-style, average evasion)

Goal: a level-appropriate melee mob that fights roughly like a same-level Warrior.

  1. Web app Mob Editor → open or create the mob. Set Level and Attack damage in the Combat section as usual.
  2. Web app Combat Simulator: "Load class…" → Warrior at this mob's Level → note the computed ATK readout.
  3. Web app Mob Editor → Combat Pipeline section: set ATK to that number (or close to it — same-level "fights like a Warrior" is the goal, not an exact match). Attack parryable = Yes.
  4. Web app Leave Avoidance Dodge/Parry/Riposte at the default (20/20/20) for an average, not-especially-evasive defender. Save.
  5. Unity Restart the host. Fight it — expect the usual Miss/Glancing/Hit/ Solid/Good spread, shifted by your relative level.

Recipe B — An evasive, unparryable beast

Goal: a wolf/wildcat-style mob that dodges often and can't be Parried (it has no weapon).

  1. Web app Combat Pipeline section: Attack parryable = No (bites/claws skip Parry, going straight to Dodge).
  2. Web app Raise Avoidance Dodge well above default — e.g. 100 lands around 5% dodge, 150+ starts approaching the higher end of the curve (§4). Parry is moot here since the attack is unparryable; Riposte is fully independent now, so raise or leave it separately depending on whether you also want this beast to occasionally counter-attack.
  3. Web app Optionally set ATK a bit below the "straightforward brute" value from Recipe A — a beast that's hard to pin down but doesn't hit as hard when it lands. Save.
  4. Unity Restart the host. Fight it — expect more frequent "you miss" than Recipe A, from Dodge succeeding rather than a low Hit Roll tier.

Recipe C — A dangerous high-level boss

Goal: a mob that can land a genuinely scary hit.

  1. Web app Set a high Level and Attack damage — remember Attack damage is the Step 3 input, not the final number that lands (§8); a Solid Hit (100%) is closest to it, other tiers scale it up or down.
  2. Web app Set ATK at or above MaxAtk (see the Combat Simulator for the current value — it's a global constant, not per-mob) so this boss always rolls the Level 20 reference table's own distribution before Level Differential even applies.
  3. Web app Consider raising Avoidance Dodge/Parry/Riposte too, if you want the boss to be hard to land clean hits on as well as hard to survive.
  4. Unity Restart the host and fight it at the intended player level — the Level Differential modifier does a lot of the "this fight is dangerous" work on its own once there's a real level gap.

8. Known gaps — what's still placeholder or unimplemented

  • Mitigation (Step 4 — armor) is a complete no-op today. Whatever Step 3 computes is the final damage applied to HP, full stop. There is currently no way to give a mob "high armor" that reduces incoming damage after a hit lands — the only levers that make a mob harder to damage are the Step 1/2 levers above (a higher/lower ATK, higher avoidance) plus raw Max health.
  • Attack damage's meaning changed with 5.1. Before this pipeline existed it was a flat, guaranteed per-hit number. Now it's the Step 3 weapon base damage input: the number actually applied is Attack damage × tier% × variance. A Glancing hit does far less than the raw field value; a Good/Critical hit does somewhat more; only a Solid Hit (100%, the locked reference point) is close to the raw number.
  • A mob's Riposte counter-hit uses the original attacker's weapon numbers, not this mob's own Attack damage. If a player attacks this mob and it Riposte-succeeds, the counter-attack damage is calculated from the player's weapon base damage and stat (at a reduced multiplier) — so a heavily-geared player takes a proportionally harder counter-hit back, regardless of what this mob's own Attack damage is set to.
  • Dodge, Parry, and Riposte all share the same underlying curve shape (AvoidanceCurve.cs) — the design doc treats their real per-check curve values as an open tuning question, so all three checks map an input value to a chance % the same way, just with three now- independent inputs (2026-08-13 rework fixed the earlier bug where Parry and Riposte read the exact same number; they no longer do, but the curve function itself is still one shared shape).
  • The curve is a piecewise-linear approximation across ~11 control points (AvoidanceCurve.cs), not the design doc's full per-point table (referenced there but not included). Values between control points are linearly interpolated — close, not exact.
  • Damage variance and the per-tier damage percentages are shared, not per-mob. One CombatTierDamageConfig asset (Resources-optional; placeholder defaults if absent) applies to every mob and player alike — there's no way to give one mob "less variance" or "a bigger Critical bonus" than another from the Mob Editor today.
  • The MinAtk/MaxAtk band is a 5.1.5 placeholder — picked to keep a level-1 fresh Warrior near the Level 1 reference table and a fully weapon-trained level-20 Warrior near the Level 20 reference table, not locked down by the design doc. Tune via the Combat Simulator. Offense and Defense's per-level caps (level × 5, fixed constants) aren't per-class tunable — neither is authored per class at all anymore (2026-08-13 rework); a class differentiates purely through its base stats now.
  • Weapon damage/delay stay hand-authored, unformalized (5.1.5 AD10). The Item Editor shows a live raw damage/delay ratio next to those two fields as a tuning-visibility aid — there's no target-DPS-by- level curve or enforced formula, since itemization variance (a slow hard-hitter vs. a fast weak weapon) is often an intentional design choice.

9. Troubleshooting

SymptomLikely cause / fix
This mob's hit distribution feels much harsher or softer than intended against a specific opponentCheck the Level gap first — the Level Differential modifier is large (up to 100 weight units) and applies on every swing. Then check this mob's ATK against the MinAtk/MaxAtk band in the Combat Simulator — an ATK already at/past MaxAtk means Level Differential is the only thing left that can make it hit harder.
This mob never lands a Critical, even when clearly favoredCritical can gain weight from a Level advantage even starting from 0 — check the opponent's actual level first. Crippling never gains weight from any modifier — it only appears if the mob's ATK is so far past MaxAtk it clamps into the Level 20 reference table's own nonzero Crippling weight (§5, §8).
My web edit to the Combat Pipeline section didn't change in-game behaviorUnity loads mob content at host start — restart the Unity host. Also confirm Postgres + the API are running.
A mob's Riposte counter-hit seems to scale with the player, not the mobExpected — see §8. The counter uses the original attacker's weapon numbers, not this mob's Attack damage.
An "Attack parryable = No" mob still gets Riposted or Dodged againstExpected — the parryable flag only skips the Parry check; Riposte and Dodge still run normally (§6).
