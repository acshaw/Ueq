Spawn System — User Guide

1. The big picture

Making something appear in the world is two separate jobs:

  1. Define the creature — what it is: name, health, damage, faction, XP, loot, and which 3D body it wears. This is data, authored in the web editors (this app) and stored in the database. Think of it as the creature's character sheet.
  2. Place a spawn — where and how it appears: you drop a Spawn Point into the Unity scene and tell it which creature (or weighted list) to spawn, how many, how often, and how it moves. This is done in the Unity editor.
Mental model: the Mob Definition is the recipe; the Spawn Point is the oven that bakes copies of it at a spot in the world. One recipe can be used by many spawn points; one spawn point can roll from a weighted list of recipes.

The three programs involved

  1. Postgres (the database) — started with Docker: docker compose up -d.
  2. The web app (this UI + the small API) — started from a terminal; the browser UI is where mobs, spawn tables, loot, factions, etc. are authored.
  3. Unity — hosts the game server, which loads all content from the database when the host starts.
⚠️ Important: Unity reads the database once, at host start. If you edit a mob in the web app while the game is running, restart the Unity host to see the change.

2. Key concepts

  • Mob id — a mob's unique internal name (e.g. goblin_scout). Spawn points and spawn tables reference mobs by this id. Distinct from the display name ("Goblin Scout") players see.
  • Spawn Point — a GameObject in the scene that spawns mobs when a player is near. Its yellow wire sphere is its activation radius.
  • Activation — a spawn point checks every 5 seconds whether a player is within its activation radius (default 50 units). If yes and nothing is alive there, it spawns.
  • Respawn — when everything a spawn point spawned has died, it waits for the respawn timer, then spawns again (while a player is still nearby; otherwise it spawns fresh the next time a player arrives).
  • Movement mode — how a mob moves when not fighting: leash (default), wander region, free-range, or patrol (§5).
  • Aggro — whether a mob attacks a player. Driven by faction standing, not the spawn system. A mob with no faction just stands there peacefully.
  • Mob body / model — the visible Synty 3D character, assigned separately from stats (§6). A mob with no assigned body shows a placeholder white cube.

3. Two spawn styles: single mob vs. spawn table

A Spawn Point spawns in one of two ways. It uses the first field that's filled in:

Field on the Spawn PointBehaviorUse it for
spawnTableId (highest priority)Rolls a weighted random mob, can spawn a group, uses the table's respawn timer Wilderness camps, varied encounters, packs
mobIdSpawns one specific mob, respawns after a default 5-minute timerUnique/named NPCs (a vendor, a boss, a quest-giver)

If both are set, the spawn table wins. If neither is set, the spawn point warns and does nothing.

4. The lifecycle of a spawn

  1. Idle — no player nearby. Nothing spawned.
  2. Player enters the activation radius (checked every 5s) → the spawn point spawns its mob(s). A spawn table rolls an entry and spawns groupSize copies (spread out so they don't stack); a single mob spawns one. Each is dropped onto the ground/navmesh so it sits on hills correctly.
  3. Mobs live and behave — wander/patrol, aggro nearby players by faction, chase, fight, and (on losing their target) return and heal.
  4. All spawned mobs die → the spawn point starts the respawn timer (table timer = base ± variance; single mob = 5 minutes). If a player is still nearby when it elapses → respawn; if not → it spawns fresh the next time a player arrives.

5. Movement modes

When a mob isn't fighting, its idle movement is one of four modes. A Spawn Point picks the mode by which field is set — checked in this order (first match wins):

PrioritySet this on the Spawn PointModeWhat the mob does
1Patrol RoutePatrolWalks an ordered loop of waypoints; resumes its beat after a fight
2Wander RegionBounded wanderWanders randomly inside an authored box/sphere, ignoring its spawn spot
3Free Range (checkbox)Free-range wanderWanders the whole zone
4(none of the above)Leash wander (default)Wanders within wanderRadius of its spawn point (from the Mob Definition, default 10u)
  • A Stationary mob (its Mob Definition's movementType = Stationary) ignores regions/free-range — it just stands at its spawn.
  • Chasing is never limited. A mob chases its target until the target dies or leaves the zone — movement modes only shape idle wandering. When a target zones out, the mob disengages and returns to its idle behavior.
  • After a fight: a leashed mob walks home to its spawn and heals; a roaming mob (region/free-range) resets where it stands; patrollers walk back and rejoin the nearest waypoint.

6. Giving a mob a body (the 3D model)

A mob's stats (Web app) and its 3D body (Unity) are separate. Skip this and the mob spawns as a plain white cube. There are two ways to give it a body — both done by hand in Unity, no menu commands.

Option 1 — the Mob Model Catalog asset

A catalog asset maps a Model Id to a body prefab. It lives at Assets/Resources/MobModelCatalog.asset.

  1. Unity If the asset doesn't exist yet: in the Project window open Assets/Resources/, right-click → Create → Ueq → Mob Model Catalog, and name it exactly MobModelCatalog. (It must sit directly under a Resources folder.)
  2. Unity Select the asset. In the Inspector, under Entries, click + to add a row.
  3. Unity Set the entry's Model Id to your mob id (e.g. goblin_scout) and drag a rigged Synty character prefab into the Prefab field (a character prefab with a SkinnedMeshRenderer + Animator, not a raw .fbx). By default a mob looks for a body whose Model Id equals its mob id; you can instead set an explicit Model Id on the Mob Definition (Web app) so several mobs share one body.
  4. Unity (Optional, non-Humanoid bodies) if a body isn't a Humanoid rig, set the entry's Animator Controller so it animates with its own clips. Leave it blank for normal Humanoid Synty characters.

Option 2 — the folder convention (simplest)

Unity Drop a rigged character prefab named exactly like the mob id (e.g. goblin_scout.prefab) into Assets/Resources/MobModels/. It's found automatically at runtime — no catalog entry needed. (Create the MobModels folder under Resources if it isn't there.)

7. Recipes (step-by-step examples)

These assume Postgres + the web app are running, and you have the game scene open in Unity. Every step is tagged by where you do it. After any Web-app change, restart the Unity host before testing.

Web app in this browser UI Unity in the Unity editor (Hierarchy / Inspector / Scene)
Ready-made drag-in prefabs live in Assets/Prefabs/Encounters/ — SpawnPoint, WanderRegion, and PatrolRoute. Drag one from the Project window into the scene, position it, and fill in its fields — no menu commands. Each already has the right component and sensible defaults (the PatrolRoute even ships three example waypoint children). You can still build any of them by hand (an empty GameObject + the matching component); the prefabs just save that step. A Spawn Point drops its mob onto the ground/navmesh at runtime (Snap To Ground is on by default), so placing it roughly above walkable ground is enough.

Recipe A — A single named NPC at a fixed spot

Goal: one "Old Hermit" that always appears by the well.

  1. Web app Author the mob in the Mob Editor: id old_hermit, display "Old Hermit"; set health; leave the faction empty so he's peaceful. Save.
  2. Unity Give him a body (§6): add a catalog entry with Model Id old_hermit and a character prefab, or drop old_hermit.prefab into Assets/Resources/MobModels/.
  3. Unity Place the spawn point: drag Assets/Prefabs/Encounters/SpawnPoint.prefab from the Project window into the scene, and position it just above the ground by the well (drag it in the Scene view, or set its Transform position). Rename it e.g. OldHermitSpawn if you like.
  4. Unity In its Spawn Point component set Mob Id = old_hermit (leave Spawn Table Id empty).
  5. Unity Save the scene (Ctrl+S), then restart the Unity host so it loads the new mob.
  6. Unity Test: Play as Host, walk near the well — the Old Hermit spawns and stands around.

Recipe B — A wilderness camp with a weighted mix (spawn table + groups)

Goal: a clearing where mostly goblins spawn, occasionally a bigger brute, sometimes in pairs.

  1. Web app Author the mobs (Mob Editor): e.g. goblin_scout and goblin_brute, each with a hostile faction (§8), XP reward, and a loot table.
  2. Unity Give each a body (§6).
  3. Web app Author a spawn table (Spawn Editor): id greenwood_goblins. Entry 1: mob goblin_scout, weight 4, group size 2. Entry 2: mob goblin_brute, weight 1, group size 1. Respawn timer base 45, variance 15 (~30–60s). Save. (Weights are relative — scouts appear 4× as often as brutes.)
  4. Unity Place the spawn point: drag Encounters/SpawnPoint.prefab into the scene over the clearing, rename it GoblinCamp. Set Spawn Table Id = greenwood_goblins (leave Mob Id empty).
  5. Unity Save the scene, then restart the Unity host.
  6. Unity Test: walk into the clearing — a weighted roll spawns either a pair of scouts or a brute; when all are dead it respawns after the timer.
Unity Duplicate the spawn-point GameObject (Ctrl+D) and move the copies around to fill a larger area with the same encounter mix — they all share the one greenwood_goblins table.

Recipe C — A mob that roams a bounded area (Wander Region)

Goal: a wolf that patrols a meadow, not tied to one bush.

  1. Web app Author dire_wolf (hostile faction). Unity Give it a body (§6).
  2. Unity Place the spawn point: drag Encounters/SpawnPoint.prefab in, set Mob Id = dire_wolf.
  3. Unity Place the region: drag Encounters/WanderRegion.prefab into the scene, rename MeadowRegion, position it at the meadow center over walkable ground. On its Wander Region component set Shape (Box or Sphere) and its size (Box Size or Sphere Radius) so the green gizmo covers the meadow.
  4. Unity Link them: select the Spawn Point → drag the MeadowRegion object into its Wander Region field.
  5. Unity Save the scene, restart the host, test: the wolf wanders anywhere inside the green volume, ignoring where it spawned.

Recipe D — A free-range wanderer

Goal: a lone ghost that drifts across the whole zone.

  1. Web app Author lost_ghost. Unity Give it a body (§6).
  2. Unity Place the spawn point: drag Encounters/SpawnPoint.prefab in, set Mob Id = lost_ghost.
  3. Unity On the Spawn Point, tick Free Range (leave Wander Region empty). Optionally raise Free Range Radius to widen roaming (the default is safe — keep it comfortably under the distance between zones).
  4. Unity Save the scene, restart the host, test: it roams the zone's walkable area.

Recipe E — A patrolling guard

Goal: a city guard that walks a fixed route down the road and back.

  1. Web app Author city_guard (usually a guard faction friendly to players, so it won't attack you). Unity Give it a body (§6).
  2. Unity Place the route: drag Encounters/PatrolRoute.prefab into the scene, rename GuardPatrol. It comes with three child waypoints — position each child at a post along the road (the blue line + numbers in the Scene view show the path). Add or delete child GameObjects to change the number of posts; child order = walk order. On the Patrol Route component set Loop (walk the loop) or uncheck it (ping-pong), and Pause Per Point (seconds paused at each post).
  3. Unity Place the spawn point: drag Encounters/SpawnPoint.prefab in, set Mob Id = city_guard, then drag the GuardPatrol object into its Patrol Route field.
  4. Unity Save the scene, restart the host, test: the guard walks its beat, aggros anything hostile it perceives, and returns to the nearest post afterward.

8. Aggro in one paragraph

Whether a mob attacks you is decided by faction standing, not the spawn system. In the web editors you give a mob a faction; every player has a numeric standing with every faction (seeded from their race). When a mob perceives a player within its perception radius, it looks up that standing: low enough → it attacks; middling → it warns; friendly → it ignores/greets you. So a peaceful NPC (vendor, quest-giver) gets no faction (or one players stand well with), and a hostile monster gets a faction players stand poorly with (e.g. a "Monster" faction set hostile to all races, authored in the Faction Editor).

9. Troubleshooting

SymptomLikely cause / fix
Mob spawns as a white cubeNo body assigned. Do §6 (catalog Model Id = mob id).
Nothing spawns when I walk upNot within the activation radius (default 50u); or neither spawnTableId nor mobId is set; or you're not running as Host/Server (spawns are server-side). Check the Console for a [SpawnPoint] warning.
My web edit didn't show upUnity loads content at host start — restart the Unity host. Also confirm Postgres + the API are running.
Mob won't wander into its region / stands stillThe Wander Region (or the spawn) isn't over the navmesh. Move it over walkable ground; confirm the green volume overlaps the blue navmesh. Also confirm the mob's movementType is Wander, not Stationary.
Mob ignores my Wander RegionA Patrol Route is also set (patrol wins). Clear it. Or the mob is Stationary.
Mob isn't hostileIt has no faction, or the player's standing with its faction is high. Give it a hostile faction (§8).
Mob chases forever / off the mapBy design chasing has no distance leash; it stops when the target dies or zones out.
Mob spawns floating or buriedSnap To Ground is off, or there's no ground collider / navmesh under the point. Keep Snap To Ground on and place over baked navmesh.

Spawn Point fields (Unity Inspector)

mobIdA single DB mob to spawn (used if no spawn table).
activationRadiusHow close a player must be to trigger spawning (default 50).
patrolRouteOptional patrol path (movement priority 1).
wanderRegionOptional bounded roam area (movement priority 2).

snapToGround / groundMask / navSampleRadiusPlacement onto the ground + navmesh.

Mob Definition fields (Mob Editor)

Identity (display name, level, model id) · Combat (max health, attack damage, attack interval, attack range) · Movement (movement type Wander/Stationary, move speed, wander radius, wander pause min/max) · AI (perception radius, base aggro threat) · Faction (faction + aggro/warning standings + on-kill faction hits) · Loot (loot table id) · Rewards (XP reward) · Vendor/Conversation ids (for shop/dialogue NPCs).

Drag the ready-made prefabs from Assets/Prefabs/Encounters/ into the scene — no menu commands. Save the scene (Ctrl+S) after, and restart the host to load Web-app content changes. (Each can also be built by hand: an empty GameObject + the matching component; the prefabs just carry the component and defaults.)
